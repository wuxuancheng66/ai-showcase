iPhone Server

An iPhone automation prototype written in Swift. The app receives tasks on the phone and uses WebDriverAgent and XCTest for screen interactions.

Use system APIs when a screen is unnecessary

The app can read the battery level, charging state, and iOS version directly from system APIs. A known deep link can open a destination without searching the screen for a button. The Swift module shows how the app decides whether an entire request can be handled by the read-only path.

View the Swift module and tests ↗

Check what happened after each action

The prototype observes the screen again after acting and looks for a clearer target when the result is ambiguous. Tasks that were running when the app quit are marked as interrupted so their outcome can be checked before retrying. It has code-level confirmation for some actions, including sending messages. Generic taps have limited coverage.

Prototype limits

The original prototype requires a WebDriverAgent session, code signing, and developer authorization on the device. The public material includes this case study and the read-only module. CoreDevice support and an MCP interface are still unverified.
