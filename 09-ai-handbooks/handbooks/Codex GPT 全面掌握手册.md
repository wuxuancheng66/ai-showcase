# 第 1 章　认知框架：Work 与 Codex 的真实分工

## 1.1 为什么你会困惑（新手必经之路）

几乎每个刚开始用 ChatGPT 桌面版的人都会问："Work 和 Codex 到底有什么区别？我该用哪个？"

你可能会发现：**ChatGPT Work 现在也能操作电脑**（@电脑、@Chrome 在 Work 模式下同样可用），下载安装、整理文件、填表都很方便。这不是错觉——之前"Work 不能操作电脑"的说法**过于绝对**了。

真正的区别不是"能不能操作"，而是**操作得多深、多稳、能扛多大的活**：

- **ChatGPT Work**：像一位"全科助理"。轻量桌面操作很方便，深度思考、查资料、写初稿、出方案是它的强项；但遇到批量处理、写代码、长任务自主执行，它偏向"聊一步做一步"。
- **Codex**：像一个不知疲倦的"执行者"。它被训练成"自己写代码 → 自己运行 → 自己看结果 → 自己纠错"的闭环，擅长批量处理、分析数据、写脚本、长耗时多步骤任务，直到把成品交付到你手里。

## 1.2 核心差异对照表

| 维度 | ChatGPT Work | Codex |
|---|---|---|
| 角色 | 轻量操作 + 规划/研究 | 深度执行 + 批量 + 长任务 |
| 操作电脑 | ✅ 可以（轻量桌面操作） | ✅ 可以（更强、更稳） |
| 批量处理（几十上百个文件） | ⚠️ 一次做一件，容易累 | ✅ 写脚本批量跑 |
| 长任务自主循环 | ⚠️ 弱，聊一步做一步 | ✅ 强，自己迭代直到完成 |
| 代码 / 脚本 / 调试 | ❌ 基本不支持 | ✅ 主场 |
| 生成成品（报告/图表/网页） | ⚠️ 偏弱 | ✅ 强，放到位 |
| 适合 | 下载安装、查资料、写方案、出初稿 | 数据分析、批量处理、写代码、复杂交付 |

## 1.3 什么场景用哪个（速查）

| 任务 | 推荐 |
|---|---|
| 下载安装软件、整理几个文件、填表 | **Work**（方便顺手）或 Codex @电脑 |
| 批量处理（200 个文件分类、100 份 PDF 提取要点） | **Codex** |
| 分析数据、出统计表和报告 | **Codex** |
| 头脑风暴、查资料、写方案初稿 | **Work** |
| 写代码 / 脚本 / 调试 | **Codex** |
| 长耗时、多步骤自主任务 | **Codex** |
| 操作当前浏览器（查资料、填表单） | Work 或 Codex @Chrome |

## 1.4 判断口诀（记住这一条就够）

> **"点几下鼠标"能搞定的 → Work；"跑一遍脚本"才能搞定的 → Codex；又要想清楚、又要干出来 → 两个配合。**

- 打开软件、下载安装、把 3 个 PDF 合并 → Work
- 把 200 个文件分类、把 30 份政策 PDF 每篇提取 5 个要点、分析问卷出报告 → Codex
- 先想方案再执行 → Work 出提纲，Codex 去抓数据、做分析、出成品

## 1.5 最佳组合拳：军师 + 士兵

真正的聪明用法不是二选一，而是**分工**：

1. 用 **ChatGPT Work** 当军师：出方案、写提纲、查背景资料
2. 把方案交给 **Codex** 当士兵：批量处理、写代码、出报告、交付成品

例如：用 Work 写"社区数字化调研"的提纲和问卷框架，再让 Codex 去抓数据、做统计、生成报告和图表。

## 1.6 常见认知误区（先排雷）

1. ❌ "Work 完全不能操作电脑" → 现在 Work 也能操作，只是适合轻量操作；批量/深度执行要靠 Codex
2. ❌ "Codex 只适合程序员" → 它是行动导向，批量处理、数据分析等通用任务也能干
3. ❌ "开梯子（全局模式）能让 Codex 更快" → 你的模型后端是国内的，全局代理反而卡死（见 4.5）
4. ❌ "本地项目 = 完全隐私" → 文件在本地，但每次对话仍会发到云端处理
5. ❌ "AI 说的都是对的" → 一切结果都要人工核验，公共治理专业尤其如此

# 第 3 章　Codex 五大核心能力详解

## 3.1 Agent Loop（自主循环）——一切能力的根基

### 3.1.1 它是什么

Codex 的核心不是"回答问题"，而是"**完成任务**"。它会进入一个循环：

```
思考 → 行动 → 观察结果 → 再思考 → 再行动 → ……直到完成
```

例如你说"把这个项目里的所有图片压缩到 500KB 以下"，它会：自己写压缩脚本 → 运行 → 看哪些图片还超标 → 调整参数 → 再跑 → 直到全部达标。

### 3.1.2 你能得到什么

- 长任务可持续运行数小时，你不用一直盯着
- 你的角色从"执行者"变成"**监督者**"：给目标、定边界、验收结果
- 遇到错误它会自己读报错、自己修，而不是停下来问你"怎么办"

### 3.1.3 用好它的三个要点

1. **目标要具体**：不只是"整理我的文件"，而是"把桌面上所有 PDF 按'课程/证件/其他'三个文件夹分类"
2. **边界要清楚**：告诉它"只动桌面，别碰下载文件夹"
3. **验收标准要明确**：告诉它"完成后列出每个文件夹的文件数量"

### 3.1.4 什么时候它会停下来问你

- 需要删除文件（尤其 rm 命令）
- 需要联网下载安装东西
- 遇到无法判断的歧义

这是它的安全机制，不是"卡住了"。

## 3.2 Computer Use（@电脑）——让 AI 真正"动手"

### 3.2.1 基础用法

在输入框输入 `@电脑` 然后直接说人话：

- `@电脑 打开 Safari，去百度下载最新版 Chrome 并安装到应用程序文件夹`
- `@电脑 打开 Finder，把桌面所有 PDF 整理到"PDF合集"文件夹`
- `@电脑 打开系统设置，把 Wi-Fi 关掉再重新打开`

### 3.2.2 权限要求（缺一不可）

首次使用会弹 macOS 权限申请：**屏幕录制** + **辅助功能**，缺一不可，授予后彻底重启 Codex。四类权限的详细说明见第 4.1 节。

### 3.2.3 后台 vs 前台（Mac 用户重点关注）

- 从 2026 年 4 月更新（v26.415）起，Mac 上 Computer Use **默认后台运行**，不抢你的鼠标
- 2026 年 5 月起还支持**锁屏运行**：锁上电脑它继续干活
- Windows 上是前台接管模式，会看到鼠标自己动，期间别动鼠标

### 3.2.4 进阶技巧

- `@电脑 在 Chrome 里……`：指定应用，定位更准
- 把常用 App 加入"始终允许"列表，减少弹窗
- 配合 Appshots（双击双 Command）先"喂"上下文，再让它操作，成功率更高

## 3.3 Skills（技能包）——把固定流程变成"一键调用"

### 3.3.1 什么是技能

技能是一个 `SKILL.md` 文件，里面写着一套"遇到这类任务就按这个流程做"的说明书。装好后，你说一句话就能触发整套流程。

### 3.3.2 你本机已有哪些技能

**系统自带**：
- `imagegen`：生成/编辑图片
- `openai-docs`：查 Codex / OpenAI 官方文档
- `skill-creator`：教你自建技能
- `skill-installer`：帮你安装 GitHub 上的技能
- `review-agent`：代码审查

**本次新装**：
- `goal-agent-team`：模糊目标 → 对齐需求写文档 → 自动规划执行
- `goal-agent-team-auto`：无人值守版，几乎不用问你就跑完

**插件自带**：documents、spreadsheets、presentations、pdf、browser、chrome、computer-use、visualize 等

### 3.3.3 如何调用

新开对话后，技能会自动出现在可用列表里。使用方式：
- 直接说："用 goal-agent-team 处理这个需求：……"
- 或让 Codex 自己判断："帮我做个……"（它会按描述自动选技能）

### 3.3.4 自建技能（进阶，详见 10.1）

把你反复做的流程（比如每周写治理周报）做成专属技能，以后一句话触发。

## 3.4 Automations（自动化任务）——定时自动干活

### 3.4.1 典型场景

"每天早上 8 点，自动搜索 AI 行业最新动态，生成日报存到本地文件夹。"

### 3.4.2 两种运行位置（务必分清）

| 位置 | 在哪跑 | 特点 |
|---|---|---|
| 工作（云端） | OpenAI 服务器 | 关电脑也能跑，但不能碰你本地文件 |
| 在你的电脑上运行 | 你的 Mac | 能操作本地文件/软件，但需开机联网 |

**要存本地文件必须选"在你的电脑上运行"。**

### 3.4.3 设置要点

1. 描述任务 + 指定时间（如"每天 8:00"）
2. 要求"每条信息必须附来源链接"
3. 首次先手动运行一次验证
4. 敏感操作保持"手动审批"

## 3.5 /goal 目标模式——把模糊想法变成任务书

- 输入 `/goal 一句话目标`，Codex 会生成详细任务书并自动执行
- 适用：目标清晰、多步骤、跨应用的任务（多页报告、跨文档调研）
- 消耗 token 比普通对话高，配合 DeepSeek 成本可接受
- 权限弹窗多时：设置 → 通用 → 权限 → 开"自动审查"

## 3.6 主任务与子任务——"大脑"和"小兵"

### 3.6.1 概念

- **主任务**：你在对话框说的最终目标（一句话，不限定步骤）
- **子任务**：主代理拆解出的具体工作包（分析文件、跑测试、查资料）

### 3.6.2 关键认知

- Codex **不会自动派生子代理**，必须你在提示词里明确说："用两个并行 Agent……"
- 子代理适合"读"的活（探路、跑测试、翻日志），不适合"写"的小活（拆了反而慢）
- 多个 Agent 同时改同一片代码容易撞车，慎用

### 3.6.3 什么时候值得拆

| 类型 | 例子 | 建议 |
|---|---|---|
| 值得拆 | 探索项目结构、跑测试、翻日志、做摘要 | ✅ 并行 |
| 值得并行 | 认证/数据库/API 各查各的 | ✅ 并行 |
| 别拆 | 一句话能说清的小修改 | ❌ 徒增成本 |
| 慎用 | 多个 Agent 改同一批文件 | ⚠️ 协调成本高 |

# 第 4 章　Mac 权限与沙箱（安全与自由的平衡）

## 4.1 macOS 四类系统权限

| 权限 | 作用 | 缺失后果 |
|---|---|---|
| 屏幕录制 | Codex"看见"屏幕 | Computer Use / Appshots 失效 |
| 辅助功能 | 模拟鼠标键盘 | 无法操作应用 |
| 麦克风 | 语音聊天/听写 | 语音设置异常 |
| 输入监控 | 全局快捷键/听写热键 | 别的 App 里按热键无反应 |

**授予后必须完全退出并重开 Codex 才生效。**

### 4.1.1 关于"输入监控"的隐私解释

这个权限让应用"看见"你按了哪些键，目的是实现全局快捷键（如 Cmd+Shift+Space 呼出对话框）。正规大厂不会偷偷记录你的键盘输入——它只在设定热键被按下时才响应。不放心可以"用前开、用完关"。

## 4.2 沙箱三档

| 档位 | 能力 | 适用 |
|---|---|---|
| 只读 Read-only | 只看不改、默认不能联网 | 代码审查 |
| 工作区可写 Workspace-write | 项目内自由读写，可开网络 | **日常推荐** |
| 完全访问 Danger-full-access | 无限制 | 慎用 |

**你的推荐配置（已生效）**：
```toml
sandbox_mode = "workspace-write"
[sandbox_workspace_write]
network_access = true
```

## 4.3 网页搜索四档怎么选

| 选项 | 含义 | 何时用 |
|---|---|---|
| 不允许网页搜索 | 完全离线 | 纯写代码 |
| 使用 OpenAI 索引 | 搜索引（缓存式） | 简单查概念 |
| 访问已索引的外部网页 | 搜索+读全文 | **日常首选** |
| 不受限制访问当前网页 | 操作当前页面 | 临时操作，用完切回 |

## 4.4 隐私纪律（公共治理专业特别重要）

- **本地项目 ≠ 离线**：代码在本地，对话仍发云端
- 关闭"改进模型"数据共享，减少数据被用于训练
- **涉及个人信息先脱敏**：姓名→学生A/B；学号→后4位；身份证→只留年份
- 依据《个人信息保护法》：处理他人个人信息需本人同意并告知用途；"学生身份"不构成豁免
- 一句话：**能脱敏就脱敏，能不传就不传，授权没拿到，绝对不动手。**

## 4.5 为什么开梯子（全局模式）Codex 会卡住

**这是你这台机器最容易踩的坑**：你的 Codex 大脑是**国内直连的 DeepSeek**（实测直连 0.2 秒）。而啊哈加速器默认"全局模式"会把所有流量绕道香港，DeepSeek 从香港访问被限制/超时 → Codex 一直加载不回答。

**解决**：啊哈加速器 → 设置 → 加速模式 → 切「**分流模式**」（国内走本地网，国际走加速器）。这样开不开梯子，Codex 都正常。

# 第 8 章　终极目标：国内正规中转站接入 OpenAI 原生模型（免注册 ChatGPT）

**原理（换芯不换壳）**：Codex 默认连官方接口（国内受限）。把 config.toml 里的 `base_url` 改成国内可达的 OpenAI 兼容网关，Codex 以为自己还在和官方对话，实际请求由网关转发给 GPT 等模型。**关键前提：网关必须支持 OpenAI Responses API 协议。**

## 8.2 渠道对比（按可信度排序）

| 渠道 | 能提供 GPT 吗 | 支付 | 特点 |
|---|---|---|---|
| 阿里云百炼 / 火山方舟等官方云 | 否（国产模型） | 实名+支付宝 | 最正规，但非 GPT |

| 其他第三方中转站 | 不一定 | 多样 | 需谨慎核验 |

> ✅ 已实测：`api.fenno.ai` 从你的网络可直连，接口正常（返回 API_KEY_REQUIRED），只差 Key。

## 8.3 三步接入法

### 第一步：注册拿 Key（唯一需要你动手的步骤）
1. 打开 https://api.fenno.ai → 注册（邮箱，或 GitHub/Google）
2. 登录 → 左侧【API 密钥】→【+ 创建密钥】→ 命名 `codex`，分组选 code-plan/Mini
3. 复制 `sk-` 开头的 Key（可先小额充值，支持支付宝/微信）

### 第二步：配置（二选一）

**方式 A：CC Switch 一键导入（推荐）**
- Fenno 密钥列表有【导入 CCS】按钮 → 自动写入 CC Switch
- CC Switch → 供应商列表选 Fenno → 启用 → 彻底重启 Codex

**方式 B：手动改 config.toml**
```toml
model = "gpt-5.4"              # 以 Fenno 控制台可用模型为准
model_provider = "fenno"

[model_providers.fenno]
name = "Fenno"
base_url = "https://api.fenno.ai"
env_key = "FENNO_API_KEY"      # 系统环境变量，别明文写文件
wire_api = "responses"         # 关键：Responses 协议
requires_openai_auth = false   # 第三方网关
```
然后 `echo 'export FENNO_API_KEY="sk-你的Key"' >> ~/.zshrc && source ~/.zshrc`

### 第三步：让 Codex 认识模型
新版 Codex 默认只认官方模型，自定义模型要写进 `~/.codex/cc-switch-model-catalog.json`：
```json
{ "models": [ { "model": "gpt-5.4", "displayName": "GPT-5.4 (Fenno)", "contextWindow": 1000000 } ] }
```

### 验证
1. 彻底重启 Codex
2. 模型菜单确认显示 GPT
3. 发"你是什么模型？"验证
4. 再测 @电脑 插件是否仍可用

## 8.4 风险提示（务必读）

- **数据安全**：请求经第三方转发，敏感代码/个人信息慎入
- **稳定性**：小站可能停服/倍率不透明/偷换模型
- **协议**：只支持 Chat Completions 的中转站需协议翻译，易出错
- **合规**：第三方转售 OpenAI 服务有灰色地带，建议小额、用于个人学习
- **并存**：接入后 CC Switch 可随时在 DeepSeek（便宜）和 GPT（更强）之间切换

# 第 10 章　进阶玩法与拓展内容

## 10.1 自建技能（手把手教程）

技能 = 一个文件夹 + 一个 `SKILL.md` 文件。跟着做：

**第 1 步：让 Codex 帮你建**
在对话里说：
```
用 skill-creator 帮我创建一个技能，功能是"处理班级表格时自动脱敏"：
把姓名列替换为学生1、学生2……，学号只保留后4位，身份证只留年份。
```

**第 2 步：它会生成类似结构**
```
~/.codex/skills/desensitize/
  └── SKILL.md        # 技能说明书
```

**第 3 步：SKILL.md 长这样（示例）**
```markdown
---
name: desensitize
description: 处理含个人信息的表格时自动脱敏。当用户要求脱敏时使用。
---

# 数据脱敏
1. 读取表格
2. 姓名列 → 学生1、学生2……
3. 学号列 → 只保留后4位
4. 身份证 → 只保留出生年份
5. 输出脱敏后的新表格（原文件不动）
```

**第 4 步：用起来**
新开对话，说："用脱敏技能处理这份名单"。

**技巧**：
- description 写清楚"什么时候用"，Codex 才能自动匹配

# 第 12 章　常见问题 FAQ（50 问速查）

## 基础与认知
1. **ChatGPT Work 和 Codex 到底什么关系？** 同一个桌面应用里的两种模式；Work 偏规划，Codex 偏执行。
2. **我该用哪个？** 干活用 Codex，出方案用 Work。
3. **Codex 需要编程基础吗？** 不需要，说人话就行。
4. **为什么 AI 会编造内容？** 模型是"猜"最合理的答案，不是查数据库；重要信息必须核验。
5. **AI 帮我写作业算学术不端吗？** 看学校规定；建议注明 AI 辅助情况，且必须自己理解修改。

## 安装与配置
6. **为什么我打开 Codex 一直加载？** 常见：梯子全局模式（见 4.5）或 CC Switch 没运行。
7. **为什么开梯子就卡？** 模型后端 DeepSeek 是国内直连，全局代理绕道国外导致超时；切分流模式。
8. **改了 config.toml 不生效？** 必须彻底重启 Codex（Cmd+Q 完全退出）。
9. **插件装完看不到？** 新开对话；或检查 CC Switch"保留官方登录"；或彻底重启。
10. **CC Switch 是什么？** 管理 API 供应商的工具，让 Codex 用 DeepSeek 等第三方模型。
11. **为什么模型菜单里没有 DeepSeek？** model_catalog_json 里没加；用 CC Switch 管理会自动写好。

## 权限与沙箱
12. **Computer Use 没反应？** 检查屏幕录制 + 辅助功能权限，给了后重启。
13. **Appshots 按了没反应？** 同样要两个权限；先激活目标对话。
14. **沙箱选哪个？** workspace-write + network_access=true 最平衡。
15. **为什么它删文件前要问我？** 安全机制，正常。
16. **如何彻底关闭权限？** 系统设置 → 隐私与安全性 → 对应权限取消。

## 网络与代理
17. **梯子怎么设置不卡 Codex？** 啊哈加速器 → 分流模式；或把 deepseek.com 加直连。
18. **Firecrawl 需要注册吗？** 免 Key 免费档可直接用（限速）；注册拿 Key 额度更高。
19. **Context7 收费吗？** 免费。
20. **DeepSeek API 需要梯子吗？** 不需要，国内直连。

## 模型与 API
21. **DeepSeek V4 Flash 和 Pro 区别？** Flash 快便宜，Pro 更强。
22. **GPT 和 DeepSeek 差距大吗？** 复杂长任务 GPT 更稳，日常 DeepSeek 够用。
23. **怎么在国内用 GPT？** 走中转站（第 8 章），不注册 ChatGPT 也能用。
24. **中转站安全吗？** 有风险；选有公司主体、小额充值、不传敏感数据。
25. **多模态插件是什么？** 给纯文本模型外挂"眼睛"，图片转文字再分析。

## 语音与界面
26. **听写快捷键没反应？** 给"输入监控"权限 + 重启。
27. **语音设置加载不出来？** 更新 Codex + 给麦克风权限。
28. **主题怎么换？** 设置 → 主题，或导入 JSON。
29. **怎么让回答更简洁/更详细？** 输出详细度调档，或对话里临时说。

## 插件使用
30. **@电脑 和 @Chrome 区别？** 前者操作桌面应用，后者控制浏览器（继承登录态）。
31. **Database 插件找不到？** 官方已拆成 Neon/Supabase/MotherDuck/Convex 四个。
32. **Convex 能操作微信吗？** 绝对不能，微信封闭系统。
33. **Figma 插件干嘛的？** 设计稿转代码。
34. **Build Web Apps 生成的网页能用吗？** 能，保存为 .html 双击即用。
35. **Sentry 插件需要账号吗？** 需要接 Sentry 项目。

## 数据与隐私
36. **本地项目真的本地吗？** 文件在本地，对话仍发云端。
37. **如何防止数据被训练？** 设置里关"改进模型"和"共享分析数据"。
38. **能直接上传同学信息吗？** 不行，先脱敏（姓名→学生A、学号→后4位）。
39. **脱敏后还能分析吗？** 能，分析"模式"不需要真实姓名。
40. **《个人信息保护法》管学生吗？** 管，处理他人信息需同意+告知用途。

## 故障排查
41. **对话记录"消失"了？** 切换服务商后历史分开显示；数据在 ~/.codex/sessions/。
42. **续聊老对话报错？** 消息格式不兼容，用修复工具/repair。
43. **Codex 输出乱码/中断？** 试试重新发送；长任务可分段问。
44. **内存占用高？** 并行对话开太多，关掉不用的。
45. **更新后插件没了？** 检查插件市场是否重新加载，重装一次。
46. **npm/npx 报错？** Node 环境问题，检查 node -v 和 PATH。
47. **MCP 服务启动失败？** 看 config.toml 语法（用 tomllib 验证），或 startup_timeout 调大。
48. **DeepSeek 余额不足？** 去 DeepSeek 开放平台充值。
49. **Fenno 提示 model not supported？** 改分组（选 Dedicated Pool）或改模型名。
50. **还有问题怎么办？** 把报错截图发给 Codex，让它帮你排查——你现在就在用它 😄

# 第 13 章　公共治理专业实战场景（学以致用）

> 这一章把 Codex 用在你的专业上。每个场景都给出"完整工作流 + 可直接复制的提示词"。做完一个场景，你就比班上 90% 的同学更会用 AI 了。

## 13.1 场景一：政策文本分析

**目标**：批量读懂政策文件，提取要点，形成对比表。

**第 1 步：收集材料**
把政策 PDF 放进项目文件夹（如 `政策库/`）。

**第 2 步：批量转文本**
对 Codex 说：
```
用 PDF 技能把 政策库/ 里所有 PDF 转成 Markdown 文本，存到 政策库/文本/。
每个文件单独存一个 .md。
```

**第 3 步：逐篇提取要点**
```
用 Documents 技能，对 政策库/文本/ 里的每一篇，分别提取：
1) 文件名称与发布机构 2) 发布时间 3) 核心目标（1-2句）
4) 关键任务/措施（列点） 5) 涉及的部门 6) 数据或资金安排
输出为一份"政策要点汇总.md"，每篇一节。
```

**第 4 步：做对比表**
```
把"政策要点汇总.md"整理成一张对比表：列为"文件名/机构/时间/核心目标/关键措施/涉及部门"，
输出为 CSV，方便我导入 Excel。
```

**第 5 步：生成分析报告**
```
基于对比表，写一份 800 字分析：这组政策在目标上的共同点、差异点、可能的配套关系。
注意：所有结论必须来自我给你的文本，不确定的标注"原文未提及"。
```

**避坑**：政策文件有歧义时，让 Codex 引用原文段落（"请引用原文支持你的判断"），防止它脑补。

## 13.2 场景二：舆情分析

**目标**：把一段时期的舆情评论分类、看情绪、找热点。

**提示词（批量版）**：
```
这份 CSV 是某事件的网友评论（列：时间、平台、内容），共 200 条。
请帮我：
1. 按主题给每条评论打标签（如"质疑""支持""中立""情绪化""谣言"）
2. 统计每个标签的数量和占比
3. 挑出 5 条最能代表正面和负面情绪的评论
4. 给出一段 300 字的舆情小结：主要情绪、争议焦点、建议回应方向
输出：标签后的新 CSV + 小结文档。
```

**进阶（模拟"数字治理"场景）**：
```
假设你是市政府数字治理部门的工作人员，收到这份舆情数据。
请以"如何回应公众关切、避免次生舆情"为目标，给我 3 条回应策略，
每条包含：回应口径（可直接发） + 理由 + 风险提示。
```

## 13.3 场景三：公共数据治理

**目标**：清洗、脱敏、分析一份真实感的数据表。

**完整工作流**：
```
1. 帮我把 数据/原始数据.csv 做质量检查：
   哪些列有空值？哪些列格式不统一？有没有明显的重复行？
2. 清洗后输出 数据/清洗后.csv（空值处理：数字列填 0，文本列标"未知"）
3. 脱敏：姓名列→学生1/2/3，身份证→只留年份，手机号→只留前3后4位
4. 做 3 个统计：总数、按类别分布、关键指标均值
5. 生成一份"数据治理报告.md"：数据来源、清洗规则、脱敏规则、统计结果、局限性
```

**专业提醒**：这个流程就是你在"数字政府"里会遇到的真实工作——数据质量、隐私保护、统计分析。做一次就懂。

## 13.4 场景四：政策建议与仿真

**目标**：基于数据写政策建议，并做简单的"如果……会怎样"推演。

**提示词**：
```
背景：某社区 65 岁以上老人占 30%，数字化服务使用率只有 20%。
请基于以下数据（粘贴数据），写一份 500 字的政策建议，包含：
1) 问题诊断（用数据说话） 2) 三条建议（每条：做什么、怎么做、预期效果）
3) 风险与配套措施
要求：建议要具体可执行，不要空话。
```

**仿真推演**：
```
假设建议 1（社区配备数字辅导员）实施后，使用率每月提升 3 个百分点。
请帮我做一张 12 个月的推演表：月份、累计使用率、需要的辅导员人数（按每 50 个老人配 1 人估算）。
```

**注意**：仿真结果是"模型估算"，不是真实数据，报告里要注明假设条件。

## 13.5 把四个场景串成一个学期项目

**期末大作业思路**：
1. 选一个公共议题（如"校园垃圾分类"）
2. 用 13.1 分析相关政策文件
3. 用 13.2 分析网上舆情

6. 用 Presentations 做成汇报 PPT

# 第 14 章　提示词工程进阶（让 Codex 更懂你）

## 14.1 写好提示词的五个要素

| 要素 | 问题 | 例子 |
|---|---|---|
| 角色 | 你是谁？ | "你是公共政策分析助手" |
| 任务 | 做什么？ | "提取这份文件的要点" |
| 对象 | 对什么做？ | "对 政策库/文本/ 里的每篇" |
| 格式 | 输出什么样？ | "输出为 Markdown 表格" |
| 约束 | 不许做什么？ | "不要编造，不确定就标注" |

**万能模板**：
```
你是【角色】。请帮我【任务】，对象是【对象】。
输出格式：【格式】。要求：【约束】。
```

## 14.2 防止 AI 编造的五个技巧

1. **要求引用**："所有结论必须引用原文，引用不到的标注'原文未提及'"
2. **给材料**：把材料直接贴给它，比让它"回忆"可靠
3. **少样本**：给它 1~2 个正确例子再让它做（"就像这样：……"）
4. **分步走**：大任务拆成小任务，每步核验
5. **交叉验证**：重要数字让它用两种方法算一遍，对比结果

## 14.3 让 Codex 按你的风格输出

```
请用以下风格回答：
- 先说结论，再解释
- 多用表格和列表
- 用通俗中文，避免术语
- 控制在 500 字以内
- 如果信息不确定，明确说"不确定"
```

这段"风格指令"可以放进**自定义指令**（全局生效）或每次对话开头贴一遍（单次生效）。

## 14.4 常见提示词错误（对照纠正）

| ❌ 错误写法 | ✅ 正确写法 |
|---|---|
| "帮我整理文件" | "把桌面所有 PDF 按课程名分类到对应文件夹，完成后列出数量" |
| "分析这个数据" | "分析 数据/名单.csv：30 名学生，统计男女比例、宿舍分布、AI 工具使用率，输出表格" |
| "写个报告" | "写 800 字调研报告，结构：背景/数据/发现/建议，存到 reports/调研报告.md" |
| "每天搜新闻" | "设置 Automations：每天 8:00 搜索 AI 行业动态，生成带来源链接的日报，存到本地文件夹" |

**核心原则**：任务越具体（对象 + 步骤 + 格式 + 验收标准），结果越靠谱。

## 14.5 处理模糊需求的追问技巧

当 Codex 反问"你指的是 A 还是 B？"时，别嫌烦——它在确认边界。你也可以主动说清楚：
- "我指的是 X 场景，不包括 Y"
- "预算/时间/规模是……"
- "做到能演示的程度就行，不需要生产级"

# 第 15 章　故障排查手册（报错对照速查）

## 15.1 Codex 一直加载/不回答

| 可能原因 | 判断方法 | 解决 |
|---|---|---|
| 梯子全局模式 | 关掉梯子立刻好 | 加速器切"分流模式"（见 4.5） |
| CC Switch 没运行 | 检查 127.0.0.1:15721 能否访问 | 打开 CC Switch |
| DeepSeek 余额不足 | 报错含 402/余额 | 去开放平台充值 |
| 网络波动 | 重试一次 | 稍等重发 |
| 对话太长 | 上下文超限 | 新开对话或精简 |

## 15.2 插件相关报错

| 现象 | 原因 | 解决 |
|---|---|---|
| @电脑 无反应 | 权限没给 | 屏幕录制+辅助功能，重启 |
| 插件列表里没有 | 需新对话 | 新建对话 |
| 插件"消失" | 切换 API 覆盖登录态 | CC Switch 开"保留官方登录" |
| 插件加载失败 | 市场没更新 | 检查插件市场，重装 |

## 15.3 模型/API 报错

| 报错 | 含义 | 解决 |
|---|---|---|
| model not supported | 模型名不对/分组不支持 | 改模型名或换分组 |
| 401 unauthorized | Key 无效 | 检查环境变量/CC Switch |
| 429 rate limited | 请求太频繁 | 等一下再试 |
| 402 insufficient balance | 余额不足 | 充值 |
| wire_api 相关 | 协议不匹配 | 确认 responses 协议 |
| array too long | 上下文超长 | 精简对话或修复 |

## 15.4 环境类报错

| 报错 | 原因 | 解决 |
|---|---|---|
| npx ENOENT | Node 没装/不在 PATH | 装 Node 18+ |
| MCP startup timeout | 服务启动慢 | config 里 startup_timeout_ms 调大 |
| TOML 解析失败 | 配置格式错 | 用 python tomllib 验证 |
| 磁盘空间不足 | 日志太大 | 清理 ~/.codex/logs 等 |

## 15.5 通用恢复流程（三连）

遇到任何奇怪问题，按顺序试：
1. **彻底重启**：Cmd+Q 退出 Codex 再打开（不是关窗口）
2. **新开对话**：插件/技能变更需要新对话才加载
3. **检查配置**：`cat ~/.codex/config.toml` 确认没被改坏（坏了用备份恢复）

80% 的问题这三步能解决。剩下 20% 把报错截图发给 Codex 排查。

# 第 16 章　零基础代码与命令行入门（30 分钟够用）

> 你不是程序员，但会用 Codex 后，懂一点点"代码和命令行的底层逻辑"，能让你少踩很多坑、更能看懂 Codex 在干嘛。

## 16.1 代码是什么（用生活比喻）

代码就是**写给电脑的"菜谱"**。你做菜要写"先洗菜、再切菜、下锅、调味"，代码就是"先读取文件、再处理数据、输出结果"。Codex 负责写菜谱，你负责验收菜好不好吃。

## 16.2 常见文件后缀是什么意思

| 后缀 | 是什么 | 你什么时候会碰到 |
|---|---|---|
| .py | Python 脚本（代码） | Codex 写批量处理脚本时 |
| .md | Markdown 文档（纯文本排版） | 你的日报、报告 |
| .csv / .xlsx | 表格数据 | 名单、成绩、问卷 |
| .html | 网页 | Build Web Apps 生成的东西 |
| .json | 配置文件/数据 | model_catalog、config |
| .toml | 配置文件 | Codex 的 config.toml |
| .pdf / .docx | 文档 | 政策文件、作业 |

**不用会写，但要会认**——看到文件后缀就知道它是什么，就不会乱动。

## 16.3 命令行是什么（终端 / Terminal）

命令行就是"用打字代替点鼠标"的操作方式。你不需要记住命令，**让 Codex 帮你跑**，但要知道几个最常用的（看 Codex 操作时心里有数）：

| 命令 | 作用 |
|---|---|
| `cd 文件夹` | 进入文件夹 |
| `ls` | 列出文件夹内容 |
| `cat 文件` | 查看文件内容 |
| `cp A B` | 复制文件 |
| `mv A B` | 移动/重命名 |
| `rm 文件` | 删除（**危险，Codex 删前会问你**） |
| `python3 xx.py` | 运行 Python 脚本 |
| `node -v` / `npm -v` | 看 Node 版本 |

## 16.4 怎么看懂报错（不求甚解版）

报错一般长这样：`错误类型: 错误信息 at 位置`。你只需要关注三件事：
1. **哪个文件**（红色路径）
2. **哪一行**（`line 12`）
3. **什么类型**（如 401=权限/Key 问题、404=找不到、超时=网络慢）

**不用自己修**——把报错整段复制给 Codex："这个报错是什么意思？怎么解决？"它会帮你分析。

## 16.5 让 Codex 帮你学代码

```
我是零基础，想学一点点 Python 用来处理数据。
请用大白话给我讲：变量、列表、for 循环 是什么，各给一个生活化的例子。
每讲完一个概念，出一道 10 秒能想明白的小题。
```

这样学 30 分钟，你就比"完全不懂"强很多了。

# 第 22 章　十类日常需求的"完美说法"

> 同一件事，说法不同，Codex 的完成度天差地别。这一章给你 10 类高频需求的"差的说法 vs 好的说法"对照，直接抄"好的"。

## 22.1 整理文件

❌ 差的说法：帮我整理一下文件
✅ 好的说法：
```
帮我把桌面上的所有文件整理一下：
1. PDF 和 Word 放到"文档"文件夹
2. 图片放到"图片"文件夹
3. 安装包（.dmg）放到"安装包"文件夹
4. 无法判断的列出来让我决定
完成后告诉我每个文件夹里有多少个文件。
```
**为什么好**：给了分类规则、例外处理、验收标准。

## 22.2 搜索资料

❌ 差的说法：帮我搜一下数字政府的资料
✅ 好的说法：
```
用 firecrawl 搜索"2026 数字政府 政策 数据要素"，找 5 篇权威来源
（政府官网、新华社、正规媒体优先）。
每篇给我：标题、来源、发布时间、核心观点（1-2 句）、链接。
按时间从新到旧排列，存成 Markdown 文件到 reports/资料收集.md。
```

## 22.3 处理数据

❌ 差的说法：分析一下这个表格
✅ 好的说法：
```
这是 数据/问卷.csv（120 条，列：时间、年龄、满意度1-5、建议）。
请帮我：
1. 检查数据质量（空值、异常值）
2. 统计：各年龄段的平均满意度、满意度分布
3. 把建议列按主题归类（如"流程""态度""技术"）
4. 输出：清洗后数据 + 统计表 + 主题归类结果
所有统计用 Python 计算，不要口算。
```

## 22.4 写文档

❌ 差的说法：帮我写个报告
✅ 好的说法：
```
写一份 800 字的调研报告《大学生 AI 工具使用情况小调研》，结构：
一、背景与目的（100字）
二、数据来源与方法（150字）
三、主要发现（300字，列3-4条，每条带一个数据）
四、建议（200字，分3条）
五、局限（50字）
语言：通俗中文。结尾注明"本报告基于模拟数据"。
存到 reports/调研报告.md。
```

## 22.5 做 PPT

❌ 差的说法：帮我做个 PPT
✅ 好的说法：
```
把 reports/调研报告.md 做成 8 页 PPT 大纲：
第1页 封面（标题+姓名+日期）
第2页 目录
第3页 背景与目的
第4-5页 主要发现（每页2条，配数据）
第6页 建议
第7页 局限与下一步
第8页 谢谢
每页写：标题 + 3 个要点 + 可配的图表建议。
```

## 22.6 操作电脑

❌ 差的说法：帮我下载个软件
✅ 好的说法：
```
@电脑 请帮我完成以下步骤，每一步做完告诉我结果：
1. 打开 Safari，访问 https://xxx.com
2. 找到 Mac 版下载按钮，下载 .dmg 文件到"下载"文件夹
3. 打开下载的 .dmg，把应用拖进"应用程序"文件夹
4. 打开应用确认能正常启动
如果页面打不开或找不到下载按钮，停下来问我，不要乱点。
```

## 22.7 学习一个概念

❌ 差的说法：给我讲讲区块链
✅ 好的说法：
```
请用"给公共管理大一学生讲"的方式解释区块链：
1. 先用一个生活比喻
2. 再说 3 个关键特征（每个配一个政务场景例子）
3. 说清楚"区块链在政务里能干嘛、不能干嘛"
4. 最后给我 3 个自查问题
控制在 600 字以内，多用短句。
```

## 22.8 解决报错

❌ 差的说法：这个报错怎么回事
✅ 好的说法：
```
我遇到这个报错（粘贴报错全文），请帮我：
1. 用大白话解释问题出在哪
2. 给 3 个排查步骤（从最简单开始）
3. 给可能的修复方法
4. 如果是配置问题，告诉我改哪个文件哪一行
```
**关键**：一定要**粘贴完整报错**，别只截一半。

## 22.9 自动化任务

❌ 差的说法：以后每天帮我搜新闻
✅ 好的说法：
```
帮我设置一个 Automations 自动化任务：
- 每天上午 8:00 运行
- 在"你的电脑上运行"（本地模式）
- 用 firecrawl 搜索"AI 行业动态"
- 按 H.1 日报模板生成 Markdown，每条必须带来源链接
- 保存到 /Users/wuxuancheng/Documents/AI_Daily_Reports/AI日报_日期.md
- 禁止编造，先手动运行一次验证
```

## 22.10 让 Codex 教我做事

❌ 差的说法：我不知道怎么开始
✅ 好的说法：
```
我对编程完全零基础，想做"分析校园垃圾分类情况"这个小项目。
请：
1. 先问我 3 个问题（数据从哪来、有多少、想得到什么结论）
2. 然后给我一份分步骤计划（每步有目标和预估时间）
3. 第 1 步先只做一件事：帮我把问卷模板生成出来
一次只推进一步，不要一次全做完。
```

## 22.11 一句话总结：好说法的公式

```
【角色/背景】+【具体任务】+【对象/材料】+【步骤或格式】+【约束/验收】+【遇到问题怎么处理】
```

写提示词时花 30 秒把这几样补全，Codex 的完成度能提升一倍。这也是你和大神之间的真正差距——不是工具，是**把话说清楚的能力**。
