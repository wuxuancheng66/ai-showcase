第 1 章　认知框架：Work 与 Codex 的真实分工

1.1 为什么你会困惑（新手必经之路）

几乎每个刚开始用 ChatGPT 桌面版的人都会问："Work 和 Codex 到底有什么区别？我该用哪个？"

你可能会发现：ChatGPT Work 现在也能操作电脑（@电脑、@Chrome 在 Work 模式下同样可用），下载安装、整理文件、填表都很方便。这不是错觉——之前"Work 不能操作电脑"的说法过于绝对了。

真正的区别不是"能不能操作"，而是操作得多深、多稳、能扛多大的活：

  • ChatGPT Work：像一位"全科助理"。轻量桌面操作很方便，深度思考、查资料、写初稿、出方案是它的强项；但遇到批量处理、写代码、长任务自主执行，它偏向"聊一步做一步"。
  • Codex：像一个不知疲倦的"执行者"。它被训练成"自己写代码 → 自己运行 → 自己看结果 → 自己纠错"的闭环，擅长批量处理、分析数据、写脚本、长耗时多步骤任务，直到把成品交付到你手里。

1.4 判断口诀（记住这一条就够）

"点几下鼠标"能搞定的 → Work；"跑一遍脚本"才能搞定的 → Codex；又要想清楚、又要干出来 → 两个配合。
  • 打开软件、下载安装、把 3 个 PDF 合并 → Work
  • 把 200 个文件分类、把 30 份政策 PDF 每篇提取 5 个要点、分析问卷出报告 → Codex
  • 先想方案再执行 → Work 出提纲，Codex 去抓数据、做分析、出成品

1.5 最佳组合拳：军师 + 士兵

真正的聪明用法不是二选一，而是分工：

  1. 用 ChatGPT Work 当军师：出方案、写提纲、查背景资料
  2. 把方案交给 Codex 当士兵：批量处理、写代码、出报告、交付成品

例如：用 Work 写"社区数字化调研"的提纲和问卷框架，再让 Codex 去抓数据、做统计、生成报告和图表。

1.6 常见认知误区（先排雷）

  1. ❌ "Work 完全不能操作电脑" → 现在 Work 也能操作，只是适合轻量操作；批量/深度执行要靠 Codex
  2. ❌ "Codex 只适合程序员" → 它是行动导向，批量处理、数据分析等通用任务也能干
  3. ❌ "开梯子（全局模式）能让 Codex 更快" → 你的模型后端是国内的，全局代理反而卡死（见 4.5）
  4. ❌ "本地项目 = 完全隐私" → 文件在本地，但每次对话仍会发到云端处理
  5. ❌ "AI 说的都是对的" → 一切结果都要人工核验，公共治理专业尤其如此

2.2 config.toml 逐行解读（你的核心配置文件）

配置文件位置：~/.codex/config.toml。下面是你当前配置的含义：

# 默认使用的模型提供商和模型
model_provider = "custom"          # 自定义提供商（由 CC Switch 管理）
model = "deepseek-v4-flash"        # 默认模型：DeepSeek V4 Flash
model_reasoning_effort = "high"    # 推理强度：高（复杂任务更好，略费 token）
disable_response_storage = true    # 不存响应记录（隐私偏好）
model_catalog_json = "cc-switch-model-catalog.json"  # 自定义模型目录，让 Codex 认得出 DeepSeek

# 沙箱模式
sandbox_mode = "workspace-write"   # 工作区可写：项目内自由读写
web_search = "indexed"             # 网页搜索：索引模式

# 模型提供商定义（CC Switch 本地代理）
[model_providers.custom]
name = "deepseek"
base_url = "http://127.0.0.1:15721/v1"   # CC Switch 本地代理地址
wire_api = "responses"                    # OpenAI Responses 协议
requires_openai_auth = true
experimental_bearer_token = "PROXY_MANAGED"

# 网络访问
[sandbox_workspace_write]
network_access = true              # 允许命令行联网（curl 等）

# 记忆
[memories]
generate_memories = true
use_memories = true

改配置前必做：先备份 cp ~/.codex/config.toml ~/.codex/config.toml.bak。改完要彻底重启 Codex 才生效。

第 3 章　Codex 五大核心能力详解

3.1 Agent Loop（自主循环）——一切能力的根基

3.1.1 它是什么

Codex 的核心不是"回答问题"，而是"完成任务"。它会进入一个循环：

思考 → 行动 → 观察结果 → 再思考 → 再行动 → ……直到完成

例如你说"把这个项目里的所有图片压缩到 500KB 以下"，它会：自己写压缩脚本 → 运行 → 看哪些图片还超标 → 调整参数 → 再跑 → 直到全部达标。

3.1.2 你能得到什么

  • 长任务可持续运行数小时，你不用一直盯着
  • 你的角色从"执行者"变成"监督者"：给目标、定边界、验收结果
  • 遇到错误它会自己读报错、自己修，而不是停下来问你"怎么办"

3.1.3 用好它的三个要点

  1. 目标要具体：不只是"整理我的文件"，而是"把桌面上所有 PDF 按'课程/证件/其他'三个文件夹分类"
  2. 边界要清楚：告诉它"只动桌面，别碰下载文件夹"
  3. 验收标准要明确：告诉它"完成后列出每个文件夹的文件数量"

3.1.4 什么时候它会停下来问你

  • 需要删除文件（尤其 rm 命令）
  • 需要联网下载安装东西
  • 遇到无法判断的歧义

这是它的安全机制，不是"卡住了"。

4.1.1 关于"输入监控"的隐私解释

这个权限让应用"看见"你按了哪些键，目的是实现全局快捷键（如 Cmd+Shift+Space 呼出对话框）。正规大厂不会偷偷记录你的键盘输入——它只在设定热键被按下时才响应。不放心可以"用前开、用完关"。

4.4 隐私纪律（公共治理专业特别重要）

  • 本地项目 ≠ 离线：代码在本地，对话仍发云端
  • 关闭"改进模型"数据共享，减少数据被用于训练
  • 涉及个人信息先脱敏：姓名→学生A/B；学号→后4位；身份证→只留年份
  • 依据《个人信息保护法》：处理他人个人信息需本人同意并告知用途；"学生身份"不构成豁免
  • 一句话：能脱敏就脱敏，能不传就不传，授权没拿到，绝对不动手。

4.5 为什么开梯子（全局模式）Codex 会卡住

这是你这台机器最容易踩的坑：你的 Codex 大脑是国内直连的 DeepSeek（实测直连 0.2 秒）。而啊哈加速器默认"全局模式"会把所有流量绕道香港，DeepSeek 从香港访问被限制/超时 → Codex 一直加载不回答。

解决：啊哈加速器 → 设置 → 加速模式 → 切「分流模式」（国内走本地网，国际走加速器）。这样开不开梯子，Codex 都正常。

5.1 MCP 是什么（先搞懂底层）

MCP（Model Context Protocol）= 万能 USB-C 接口。以前接一个外部工具（数据库、浏览器、视觉模型）要写专门代码；现在只要工具支持 MCP 标准协议，Codex 一行配置就能调用。

你的 Codex 里，插件（如 @电脑、@Chrome）和 MCP 服务（如 context7、firecrawl、llm-vision）都是通过这套机制接进来的。插件偏"场景功能"，MCP 偏"底层服务"，两者配合使用。

8.3 三步接入法

第一步：注册拿 Key（唯一需要你动手的步骤）

  1. 打开 https://api.fenno.ai → 注册（邮箱，或 GitHub/Google）
  2. 登录 → 左侧【API 密钥】→【+ 创建密钥】→ 命名 codex，分组选 code-plan/Mini
  3. 复制 sk- 开头的 Key（可先小额充值，支持支付宝/微信）

第二步：配置（二选一）

方式 A：CC Switch 一键导入（推荐）

  • Fenno 密钥列表有【导入 CCS】按钮 → 自动写入 CC Switch
  • CC Switch → 供应商列表选 Fenno → 启用 → 彻底重启 Codex

方式 B：手动改 config.toml

model = "gpt-5.4"              # 以 Fenno 控制台可用模型为准
model_provider = "fenno"

[model_providers.fenno]
name = "Fenno"
base_url = "https://api.fenno.ai"
env_key = "FENNO_API_KEY"      # 系统环境变量，别明文写文件
wire_api = "responses"         # 关键：Responses 协议
requires_openai_auth = false   # 第三方网关

然后 echo 'export FENNO_API_KEY="sk-你的Key"' >> ~/.zshrc && source ~/.zshrc

第三步：让 Codex 认识模型

新版 Codex 默认只认官方模型，自定义模型要写进 ~/.codex/cc-switch-model-catalog.json：

{ "models": [ { "model": "gpt-5.4", "displayName": "GPT-5.4 (Fenno)", "contextWindow": 1000000 } ] }

验证

  1. 彻底重启 Codex
  2. 模型菜单确认显示 GPT
  3. 发"你是什么模型？"验证
  4. 再测 @电脑 插件是否仍可用

第 12 章　常见问题 FAQ（50 问速查）

基础与认知

  1. ChatGPT Work 和 Codex 到底什么关系？ 同一个桌面应用里的两种模式；Work 偏规划，Codex 偏执行。
  2. 我该用哪个？ 干活用 Codex，出方案用 Work。
  3. Codex 需要编程基础吗？ 不需要，说人话就行。
  4. 为什么 AI 会编造内容？ 模型是"猜"最合理的答案，不是查数据库；重要信息必须核验。
  5. AI 帮我写作业算学术不端吗？ 看学校规定；建议注明 AI 辅助情况，且必须自己理解修改。

安装与配置

  1. 为什么我打开 Codex 一直加载？ 常见：梯子全局模式（见 4.5）或 CC Switch 没运行。
  2. 为什么开梯子就卡？ 模型后端 DeepSeek 是国内直连，全局代理绕道国外导致超时；切分流模式。
  3. 改了 config.toml 不生效？ 必须彻底重启 Codex（Cmd+Q 完全退出）。
  4. 插件装完看不到？ 新开对话；或检查 CC Switch"保留官方登录"；或彻底重启。
  5. CC Switch 是什么？ 管理 API 供应商的工具，让 Codex 用 DeepSeek 等第三方模型。
  6. 为什么模型菜单里没有 DeepSeek？ model_catalog_json 里没加；用 CC Switch 管理会自动写好。

权限与沙箱

  1. Computer Use 没反应？ 检查屏幕录制 + 辅助功能权限，给了后重启。
  2. Appshots 按了没反应？ 同样要两个权限；先激活目标对话。
  3. 沙箱选哪个？ workspace-write + network_access=true 最平衡。
  4. 为什么它删文件前要问我？ 安全机制，正常。
  5. 如何彻底关闭权限？ 系统设置 → 隐私与安全性 → 对应权限取消。

网络与代理

  2. Firecrawl 需要注册吗？ 免 Key 免费档可直接用（限速）；注册拿 Key 额度更高。
  3. Context7 收费吗？ 免费。
  4. DeepSeek API 需要梯子吗？ 不需要，国内直连。

模型与 API

  1. DeepSeek V4 Flash 和 Pro 区别？ Flash 快便宜，Pro 更强。
  2. GPT 和 DeepSeek 差距大吗？ 复杂长任务 GPT 更稳，日常 DeepSeek 够用。
  3. 怎么在国内用 GPT？ 走中转站（第 8 章），不注册 ChatGPT 也能用。
  4. 中转站安全吗？ 有风险；选有公司主体、小额充值、不传敏感数据。
  5. 多模态插件是什么？ 给纯文本模型外挂"眼睛"，图片转文字再分析。

语音与界面

  1. 本地项目真的本地吗？ 文件在本地，对话仍发云端。
  2. 如何防止数据被训练？ 设置里关"改进模型"和"共享分析数据"。
  3. 能直接上传同学信息吗？ 不行，先脱敏（姓名→学生A、学号→后4位）。
  4. 脱敏后还能分析吗？ 能，分析"模式"不需要真实姓名。
  5. 《个人信息保护法》管学生吗？ 管，处理他人信息需同意+告知用途。

故障排查

  1. 对话记录"消失"了？ 切换服务商后历史分开显示；数据在 ~/.codex/sessions/。
  2. 续聊老对话报错？ 消息格式不兼容，用修复工具/repair。
  3. Codex 输出乱码/中断？ 试试重新发送；长任务可分段问。
  4. 内存占用高？ 并行对话开太多，关掉不用的。
  5. 更新后插件没了？ 检查插件市场是否重新加载，重装一次。
  6. npm/npx 报错？ Node 环境问题，检查 node -v 和 PATH。
  7. MCP 服务启动失败？ 看 config.toml 语法（用 tomllib 验证），或 startup_timeout 调大。
  8. DeepSeek 余额不足？ 去 DeepSeek 开放平台充值。
  9. Fenno 提示 model not supported？ 改分组（选 Dedicated Pool）或改模型名。
  10. 还有问题怎么办？ 把报错截图发给 Codex，让它帮你排查——你现在就在用它 😄

13.1 场景一：政策文本分析

目标：批量读懂政策文件，提取要点，形成对比表。

第 1 步：收集材料

把政策 PDF 放进项目文件夹（如 政策库/）。

第 2 步：批量转文本

对 Codex 说：

第 3 步：逐篇提取要点

用 Documents 技能，对 政策库/文本/ 里的每一篇，分别提取：
1) 文件名称与发布机构 2) 发布时间 3) 核心目标（1-2句）
4) 关键任务/措施（列点） 5) 涉及的部门 6) 数据或资金安排
输出为一份"政策要点汇总.md"，每篇一节。

第 4 步：做对比表

把"政策要点汇总.md"整理成一张对比表：列为"文件名/机构/时间/核心目标/关键措施/涉及部门"，
输出为 CSV，方便我导入 Excel。

第 5 步：生成分析报告

13.2 场景二：舆情分析

目标：把一段时期的舆情评论分类、看情绪、找热点。

提示词（批量版）：

1. 按主题给每条评论打标签（如"质疑""支持""中立""情绪化""谣言"）
2. 统计每个标签的数量和占比
3. 挑出 5 条最能代表正面和负面情绪的评论
4. 给出一段 300 字的舆情小结：主要情绪、争议焦点、建议回应方向
输出：标签后的新 CSV + 小结文档。

进阶（模拟"数字治理"场景）：

请以"如何回应公众关切、避免次生舆情"为目标，给我 3 条回应策略，

13.3 场景三：公共数据治理

目标：清洗、脱敏、分析一份真实感的数据表。

完整工作流：

1. 帮我把 数据/原始数据.csv 做质量检查：
   哪些列有空值？哪些列格式不统一？有没有明显的重复行？
2. 清洗后输出 数据/清洗后.csv（空值处理：数字列填 0，文本列标"未知"）
3. 脱敏：姓名列→学生1/2/3，身份证→只留年份，手机号→只留前3后4位
4. 做 3 个统计：总数、按类别分布、关键指标均值
5. 生成一份"数据治理报告.md"：数据来源、清洗规则、脱敏规则、统计结果、局限性

13.4 场景四：政策建议与仿真

请基于以下数据（粘贴数据），写一份 500 字的政策建议，包含：
1) 问题诊断（用数据说话） 2) 三条建议（每条：做什么、怎么做、预期效果）
3) 风险与配套措施
要求：建议要具体可执行，不要空话。

仿真推演：

假设建议 1（社区配备数字辅导员）实施后，使用率每月提升 3 个百分点。
请帮我做一张 12 个月的推演表：月份、累计使用率、需要的辅导员人数（按每 50 个老人配 1 人估算）。

注意：仿真结果是"模型估算"，不是真实数据，报告里要注明假设条件。
