# 第 0 章　先花 10 分钟搞懂几个关键词

这一章没有操作，只有概念。但它是整本手册的地基，请你耐心看完。

## 0.1 AI 到底在做什么

把 AI 想成"读过海量书籍和网页、学会了语言规律的程序"。它处理任何问题都只做三件事：

1. **理解**你的输入（问题、文档、数据说明）；
2. 在它见过的海量模式里**匹配**最相关的内容；
3. **生成**一段新的回答。

所以 AI 特别擅长那些"**见过类似情况就能处理**"的重复性脑力劳动，比如：归纳政策要点、整理会议纪要、找数据异常、对比两份文件的异同。

**它的局限**：它不"懂"事实，它只"猜"最合理的答案。所以 AI 可能编造来源、算错数字——**一切结果都必须由你核验**。这一点全手册通用。

## 0.2 AI 参与工作的四个层次

| 层次 | 你在做什么 | AI 做什么 | 你主要在哪个工具里用 |
|---|---|---|---|
| 层次一：信息检索助手 | 提问 | 找资料、初步整理 | 对话式 AI（网页/App） |
| 层次二：内容生成与草稿 | 给方向和材料 | 出初稿，你修改定稿 | 对话式 AI |
| 层次三：工作流自动化 | 写脚本搭流水线 | 按步骤批量处理文件和数据 | **API** + Python |
| 层次四：AI Agent（智能体） | 给一个目标 | 自己规划、调用工具、逐步完成 | Agent 工具（Cursor/Claude Code 等） |

前两层不需要写代码，谁都会用；第三层是**本手册的重点**，第四层是进阶玩法。

## 0.3 Coding Plan（AI 编程订阅）是什么

"Coding Plan"不是某个产品的官方名字，圈子里通常指**包月付费的 AI 编程工具**，例如：

- **Cursor**（推荐大一新生入门，有免费版）
- **Claude Code**（命令行里的 AI 编程助手）
- **GitHub Copilot**（GitHub 出品，大学生可免费申请，见 1.4 节）

它们的作用：你打开代码编辑器，AI 在旁边**陪你写代码**——自动补全、解释代码、帮你修报错、按你的要求改代码。

特点：**交互式**（要人坐在电脑前）＋ **包月固定价**（用多用少一个价）。

## 0.4 API 是什么

API（Application Programming Interface，应用程序接口）是模型公司提供的"**程序调用入口**"。你的 Python 脚本可以像打电话一样，一次调用一次 AI，连续处理几千份文件——**不需要人坐在屏幕前**。

特点：**无人值守**（脚本自己跑）＋ **按用量计费**（按"token"计费，token 大致可以理解为一个中文词或几个英文字符）。

## 0.5 Coding Plan 和 API 什么时候用哪个

| 场景 | 用哪个 | 为什么 |
|---|---|---|
| 写代码时想让 AI 帮忙 | Coding Plan | 交互式，包月随便用 |
| 修报错、解释代码 | Coding Plan | 同上 |
| 批量处理 100 份 PDF | API | 脚本循环调用，不需要人盯着 |
| 每天自动跑一遍数据 | API | 可以定时无人运行 |
| 偶尔用一下、想省钱 | API（先充 10 元） | 按量计费，不用不花钱 |

一句话总结：**写代码靠 Coding Plan，跑批量靠 API，两者配合 = 又便宜又能干**。

## 0.6 三条必须知道的红线

1. **AI 会犯错**：编造文件、算错数字、引用不存在的"来源"都可能发生。凡是要交给老师或公开的内容，逐条核验。
2. **学术诚信**：是否允许使用 AI、如何标注，以学校和课程老师的规定为准。允许的情况下，通常要声明"哪些部分用了 AI 辅助"。
3. **隐私与安全**：不要上传身份证号、学号、未公开数据、他人隐私到任何 AI 平台；API Key 相当于你的密码，绝不外传、绝不提交到公开代码仓库。

# 第 1 章　动手前的准备（约 1 小时）

> 目标：把这五样东西准备好——① 项目文件夹　② 一个对话式 AI 账号　③ Python　④ AI 编程工具 Cursor　⑤ API Key。
> 做完第 1.7 节你就能跑通第一个"AI 脚本"，后面全都不慌了。

## 1.1 建一个"项目文件夹"

以后你每个项目（政策分析、舆情分析……）都放一个独立文件夹，别乱放。

1. 打开电脑的"文稿/Documents"文件夹。
2. 新建一个文件夹，命名为 `AI治理练习`（英文名 `AI_governance` 也可以，避免某些工具对中文路径报错）。
3. 在这个文件夹里再建两个子文件夹，分别叫 `policy_pdfs`（放政策 PDF）和 `scripts`（放 Python 脚本）。
4. 记住这个文件夹的完整路径。macOS 上通常长这样：`/Users/你的用户名/Documents/AI治理练习`。

> 小技巧：以后所有脚本、数据都放这个文件夹里，管理起来很清爽。

## 1.2 注册一个"对话式 AI"账号

对话式 AI 用于第 2、3 章（检索、起草），不花钱。

1. 用浏览器打开 DeepSeek 官网 `chat.deepseek.com`（也可以用其他同类产品，操作逻辑都一样）。
2. 点"注册"，用邮箱或手机号注册并登录。
3. 随便问它一句"你好"，确认能用。

> 为什么推荐 DeepSeek：对国内网络友好、便宜、中文好，而且它开放 API，和第 4 章用的接口是同一家，流程最顺。

## 1.3 安装 Python

Python 是你要学的第一门"能让 AI 干活"的语言。安装步骤：

**如果你是 macOS：**

1. 打开"终端"（按 `Command + 空格`，输入"终端"，回车）。
2. 输入下面这行，回车，等它运行完：
   `xcode-select --install`（如果提示已安装，就跳过）
3. 再输入下面这行，回车：
   `python3 --version`
4. 如果显示类似 `Python 3.12.x` 或更高，说明系统自带 Python，直接跳到 1.4 节。
5. 如果提示找不到命令，去官网 `python.org` 下载安装包，安装时勾选"Add Python to PATH"，装完重新打开终端再试一次。

**如果你是 Windows：**

1. 打开官网 `python.org`，点 Downloads，下载最新版安装包。
2. 运行安装包，**务必勾选**"Add python.exe to PATH"（这步很重要），然后点 Install Now。
3. 装完后按 `Win + R`，输入 `cmd` 回车，打开命令行，输入：
   `python --version`
4. 显示版本号就成功了。

> 看到版本号不等于会编程，别慌，你只需要会"运行别人写好的脚本"和"复制粘贴代码"，本手册教的就是这个。

## 1.4 安装 AI 编程工具 Cursor（这就是你的"Coding Plan"）

Cursor 是一个 AI 编程编辑器，免费版够你大学前两年用。

1. 打开 `cursor.com`，点 Download 下载对应你系统的版本。
2. 安装并打开，用邮箱或 GitHub 账号登录（免费注册即可）。
3. 打开后它会显示一个欢迎页。把 Cursor 想象成"自带 AI 助手的记事本"，你不需要先学它，第 2 步做项目时自然就会用。

**省钱彩蛋（大学生福利）**：如果你有 GitHub 账号，去 `education.github.com` 申请 GitHub 学生开发者包（GitHub Student Developer Pack），一般用学生证/学号就能认证，通过后可以**免费**使用 GitHub Copilot Pro 等一堆工具。大一入学注册好学生身份后就去申请。

## 1.5 申请 API Key 并充值（重要，跟着做）

API Key 是"你的程序调用 AI 的钥匙"。申请步骤：

1. 打开 `platform.deepseek.com`，用刚才的账号登录。
2. 左侧菜单找到"API Keys"，点"创建 API Key"。
3. 给它起个名字（比如 `我的第一个key`），创建后**立刻复制保存**到记事本里——密钥只显示这一次，关闭页面就看不到了。
4. 左侧找到"充值/费用"，先充 **10 元**。放心，这个量足够你练完本手册所有项目还有富余。
5. 记下两个信息（后面脚本要用）：
   - **API Key**：形如 `sk-xxxxxxxxxxxxxxxx`
   - **接口地址（base_url）**：`https://api.deepseek.com`

> 安全提醒：这个 Key 相当于你的密码。不要发给别人，不要传到 GitHub 上，用完的项目文件夹里也别存到会被分享的地方。

## 1.6 安装用到的 Python 库（工具箱）

库（library）就是别人写好的现成功能包。打开终端（macOS）/命令行（Windows），输入下面这行并回车：

`pip3 install openai pypdf pandas jieba matplotlib requests`

（Windows 上如果提示找不到 pip3，就换成 `pip install ...`）

看到一堆"Successfully installed"就成功了。如果报错，看第 7 章 FAQ 的"ModuleNotFoundError"这一条。

## 1.7 验证：跑通你的第一个 AI 脚本

现在做一次完整的小测试，证明"你 → Python → API → AI → 回答"这条路是通的。

1. 打开 Cursor，点菜单 File → Open Folder，选择你 1.1 节建的 `AI治理练习` 文件夹。
2. 在左侧文件列表空白处右键 → New File，新建一个文件，命名为 `hello_ai.py`。
3. 把下面的代码完整复制进去（**把 `sk-你的密钥` 换成你自己的 API Key**）：

```python
from openai import OpenAI

# 连接 AI：填你自己的密钥和接口地址
client = OpenAI(
    api_key="sk-你的密钥",          # 换成你自己的密钥
    base_url="https://api.deepseek.com"  # 接口地址
)

# 问 AI 一个问题
resp = client.chat.completions.create(
    model="deepseek-chat",         # 模型名，以平台文档为准
    messages=[
        {"role": "system", "content": "你是数字公共治理专业的助教。"},
        {"role": "user", "content": "用三句话解释什么是数字政府。"},
    ]
)

# 打印 AI 的回答
print(resp.choices[0].message.content)
```

4. 运行：在 Cursor 里按 `Command + 回车`（macOS）或 `Ctrl + 回车`（Windows），或点右上角运行按钮。
5. 如果下方输出区出现三句关于"数字政府"的中文回答，**恭喜你，全链路打通了！** 这是你掌握 API 的里程碑时刻。

如果报错，优先检查：密钥有没有粘贴对（是不是多了空格）、网络是否正常、`openai` 库是否装好（见 1.6 和 FAQ）。

# 第 2 章　层次一：信息检索助手——把 AI 当高级搜索引擎

> 这一章不写代码，用 DeepSeek 网页版就能做。目标：把"翻资料"变成"AI 先整理、你来核实"。

## 2.1 提问五要素：一个通用的提问公式

同样一个问题，问得越清楚，AI 答得越好。记住这个公式：

**「你扮演谁」+「做什么任务」+「背景/材料」+「具体要求」+「输出格式」**

示例（研究"粤港澳大湾区数字政府建设"）：

> 你是一名研究数字政府的助理研究员（角色）。请帮我梳理粤港澳大湾区数字政府建设的典型案例（任务），重点关注广州、深圳、珠海三个城市近三年的实践（背景）。请列出 5 个案例，每个案例包含：实施主体、核心做法、成效、可借鉴点（要求）。用表格输出（格式）。

对比一下"随便问"：`大湾区数字政府有什么案例？`——也能答，但答案泛泛而谈。**多花 30 秒把问题写具体，效果天差地别。**

## 2.2 三个练习（照着问一遍）

**练习 1：案例检索**
> 你是政策研究助理。请找出 5 个中国"城市大脑"建设典型案例，每个用 3 句话概括，并说明它们对公共治理的意义。

**练习 2：概念辨析**
> 请对比"数字公共治理""电子政务""智慧城市"三个概念的区别与联系，用一张表格展示，并用一句话总结各自的核心。

**练习 3：找政策文件线索**
> 请列出近三年广东省关于"数据要素市场化"的重要政策文件名称和发布机构。注意：如果你不确定，请明确标注"这条信息我无法确认，请自行核实"，不要编造。

## 2.3 三个重要习惯

1. **要求 AI 区分"事实"和"推断"**：在问题末尾加一句"请把确定的事实和你推测的内容分开标注"。
2. **关键信息一定二次核实**：AI 给的"文件名、年份、机构、数据"必须去政府官网或权威媒体确认，因为它可能记错。
3. **用追问迭代**：第一版不满意不要重开，直接追问"第 2 点再展开""换个角度""给反例"。

## 2.4 什么时候要用 API 做检索？

网页版一次只能问一次。如果你有 **10 个城市、每个要查 5 个关键词**，手动问 50 次太累——这时就交给 API 脚本批量跑（第 4 章会教你）。原则是：**一次性的小问题用网页版，成批的重复问题用 API**。

# 第 3 章　层次二：内容生成与草稿——让 AI 帮你写初稿

> 核心思路：**AI 出初稿，你改定稿**。你的时间花在"判断和修改"上，而不是"从空白文档开始憋"。

## 3.1 通用流程（四步）

1. **给材料**：把相关的文本、数据、要求发给 AI。
2. **定框架**：先让 AI 列出大纲，你确认或调整，再让它填充。
3. **出初稿**：基于大纲生成完整初稿。
4. **你改定稿**：核对事实、补充专业判断、调整语气，这是你作为"未来公共治理人才"的价值所在。

## 3.2 例子 A：把会议录音变成纪要

假设你参加了一场关于"社区数字化治理"的讨论会，录了音。

1. 先让 AI 把录音转文字（语音转文字工具很多，或用会议软件的自动转写功能），得到一份文字稿。
2. 把文字稿粘贴到 DeepSeek，输入：

> 这是某次会议的讨论文字稿。请整理成会议纪要，包含：会议主题、讨论要点（按议题分组）、达成的共识、待办事项（写明负责人和时间）。语言简洁，直接输出结果，不要客套话。
>
> 文字稿如下：
> （粘贴文字稿）

3. AI 输出纪要后，你核对：有没有漏掉关键议题？待办事项是不是会议真实提到的？改完后存档。

## 3.3 例子 B：写政策分析报告初稿

1. 把政策原文（或你收集的资料）发给 AI。
2. 输入：

> 你是政策分析助手。请基于以下材料，写一份政策分析报告初稿，结构为：一、政策背景与目标；二、主要内容解读；三、实施难点与风险；四、对数字公共治理的意义；五、完善建议。每部分 2～3 段，用通俗中文，先列大纲。
>
> 材料如下：
> （粘贴材料）

3. 先看大纲对不对，不对就让它改，对了再让它"按这个大纲写全文"。
4. 拿到初稿后，**逐条核实里面的事实**（政策条文、数字、时间），再改写成你自己的语言和观点。

## 3.4 怎么"喂"材料给 AI

- **短材料**（几千字内）：直接复制粘贴。
- **长文档**（整本政策文件）：网页版通常支持上传 PDF/Word 附件，直接拖进去。
- **特别长的资料**：让 AI 分段处理，比如"先总结第 1～10 页，再总结 11～20 页"。
- **数据表格**：粘贴 CSV 文本，或截图让它"看图"。

## 3.5 检查清单：AI 初稿你要核对什么

- [ ] 关键数字、年份、机构名称是否正确
- [ ] 引用的政策条文是否真实存在、原文是否一致

> 这一章是整个手册的核心。你会亲手搭出一条"流水线"：**收集文件 → 脚本读取 → API 分析 → 生成结果 → 人工核验**。

## 4.0 先建立"流水线"思维

想象你开了一家小工厂：

- **原料**：政策 PDF、评论数据、脏表格……
- **机器**：Python 脚本（负责读文件、整理格式）
- **工人**：AI（通过 API 被脚本一次次"喊"来干活）
- **产品**：分析结果、报告、图表

你的工作不是亲手干每一道工序，而是**设计流水线 + 检查产品质量**。这就是"用 AI 参与项目"的底层逻辑。

画成图就是：

```
文件/数据 ──► 脚本读取 ──► 调用API让AI分析 ──► 保存结果 ──► 人工核验 ──► 报告
```

## 4.1 第一个 API 脚本：批量分析多条文本

网页版一次问一条，API 脚本一次能处理几百条。先看一个能直接跑的例子：

1. 在 Cursor 里新建文件 `batch_analyze.py`（放在 `scripts` 文件夹）。
2. 复制下面代码，替换密钥：

```python
from openai import OpenAI

client = OpenAI(
    api_key="sk-你的密钥",               # 换成你的密钥
    base_url="https://api.deepseek.com"
)

# 要分析的文本列表（可以是评论、政策段落、新闻……）
texts = [
    "广州市发布了最新的数字政府建设三年行动方案。",
    "某社区试点用小程序收集居民意见，参与率明显提升。",
    "专家呼吁加强公共数据的隐私保护。",
]

for i, text in enumerate(texts, 1):
    resp = client.chat.completions.create(
        model="deepseek-chat",
        messages=[
            {"role": "system", "content": "你是政策分析助手。请提取：1）这段话的主题 2）关键信息 3）一句话评价。用简洁中文回答。"},
            {"role": "user", "content": text},
        ]
    )
    print(f"===== 第 {i} 条 =====")
    print(resp.choices[0].message.content)
    print()
```

3. 运行，看输出。如果三条都分析出来了，**你已经会用 API 了**。

**这段代码逐行在干嘛**（现在不要求全懂，但要知道每行是干嘛的）：

| 代码 | 作用 |
|---|---|
| `from openai import OpenAI` | 引入"打电话的工具包" |
| `client = OpenAI(...)` | 建立连接，告诉它"我是谁（密钥）+ 打到哪（地址）" |
| `for i, text in enumerate(texts, 1)` | 循环：对列表里每条文本 |
| `client.chat.completions.create(...)` | 打一次电话：把 system（角色设定）+ user（你的内容）发给 AI |
| `model="deepseek-chat"` | 选择用哪个 AI 模型 |
| `resp.choices[0].message.content` | 取出 AI 回复的文字 |
| `print(...)` | 打印出来 |

> **什么叫 token（计费单位）**：大致等于"一个中文词或几个英文字母"。你发给 AI 的文字和 AI 回复的文字都算 token，用完扣费。DeepSeek 很便宜，正常练习根本不用担心，具体价格以平台"价格"页面为准。

### 第 3 步　用 API 批量分析每份文件

新建 `policy_pipeline.py`，复制下面代码（替换密钥）：

```python
import json
from pathlib import Path
from openai import OpenAI

client = OpenAI(
    api_key="sk-你的密钥",
    base_url="https://api.deepseek.com"
)

SYSTEM_PROMPT = (
    "你是政策分析专家。请从政策文本中提取："
    "1) 文件主题 2) 核心目标 3) 关键条款（3-5条）4) 主要实施手段 "
    "5) 可能的难点。用中文回答，分点列出。"
)

results = {}
for txt_path in sorted(Path("policy_texts").glob("*.txt")):
    text = txt_path.read_text(encoding="utf-8")[:6000]  # 控制长度、控制费用
    resp = client.chat.completions.create(
        model="deepseek-chat",
        messages=[
            {"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user", "content": text},
        ],
        temperature=0.3,          # 数值越低，回答越"稳定老实"
    )
    results[txt_path.stem] = resp.choices[0].message.content
    print(f"完成：{txt_path.stem}")

Path("政策分析结果.json").write_text(
    json.dumps(results, ensure_ascii=False, indent=2), encoding="utf-8"
)
print("全部完成，结果已保存到 政策分析结果.json")
```

运行后，项目文件夹里会出现 `政策分析结果.json`——用 Cursor 打开它，就能看到每份政策的分析结果。

### 第 2 步　用 API 做情感分类

新建 `sentiment.py`：

```python
import csv
from collections import Counter
from openai import OpenAI

client = OpenAI(
    api_key="sk-你的密钥",
    base_url="https://api.deepseek.com"
)

# 读取评论（假设第一列是评论文本）
comments = []
with open("评论数据.csv", encoding="utf-8") as f:
    for row in csv.reader(f):
        if row:                     # 跳过空行
            comments.append(row[0])

def classify(text):
    resp = client.chat.completions.create(
        model="deepseek-chat",
        messages=[
            {"role": "system", "content": "判断这条评论的情感倾向，只回答三个词之一：正面/负面/中性。"},
            {"role": "user", "content": text},
        ],
        temperature=0,              # 0 = 尽量稳定，不要发挥
    )
    return resp.choices[0].message.content.strip()

counts = Counter()
for c in comments[1:]:              # 跳过表头
    label = classify(c)
    counts[label] += 1
    print(f"{label}\t{c[:25]}")

print("\n情感分布：", dict(counts))
```

运行后，你会看到每条评论的标签和整体分布。

> **省钱小技巧**：情感分类这种简单任务，token 消耗很小，几十条评论也就几分钱。真正贵的是让 AI 写长文章，所以"能本地算的用代码，AI 只做它擅长的判断"。

```python
import pandas as pd

df = pd.read_csv("原始数据.csv", encoding="utf-8")

# 1) 删除完全重复的行
df = df.drop_duplicates()

# 2) 删除年龄列中无法转为数字的行
df["年龄"] = pd.to_numeric(df["年龄"], errors="coerce")
df = df.dropna(subset=["年龄"])
df["年龄"] = df["年龄"].astype(int)

# 3) 统一日期格式
df["提交时间"] = pd.to_datetime(df["提交时间"], format="mixed").dt.strftime("%Y-%m-%d")

# 4) 去掉文本列首尾空格
for col in df.select_dtypes(include="object").columns:
    df[col] = df[col].str.strip()

# 5) 保存
df.to_csv("清洗后数据.csv", index=False, encoding="utf-8-sig")
print("清洗完成，剩余行数：", len(df))
```

```python
counts.plot(kind="bar", figsize=(6, 4), title="各区提交数量")
plt.xticks(rotation=0)
plt.savefig("各区数据分布.png", dpi=150, bbox_inches="tight")
print("已保存：各区数据分布.png")
```

## 4.5 场景四：政策建议与仿真

**项目目标**：给 AI 一份政策草案，让它扮演"仿真器"，模拟政策对不同群体的影响、识别风险、提出优化建议。

> 这里的"仿真"不是真正用数学模型跑模拟，而是**让 AI 基于它的知识，系统性地推演政策可能的影响面**。它的价值是"逼你考虑周全"，不是"替你下结论"。

### 第 1 步　准备政策草案

新建 `政策草案.txt`，写一段你自己的政策设想（大一新生不用写得多专业，有想法就行），例如：

```
关于在社区推广"AI 政务问答机器人"的试点方案（草案）
一、目的：在 10 个社区部署 AI 问答机器人，解答居民关于社保、户籍、办事流程的常见问题，缓解窗口压力。
二、内容：机器人提供 7×24 小时在线问答；对无法回答的问题转人工；收集高频问题用于优化。
三、保障：需要数据支持、系统维护经费、居民使用培训。
```

### 第 2 步　用 API 做"多维度影响仿真"

新建 `simulation.py`：

```python
import json
from pathlib import Path
from openai import OpenAI

client = OpenAI(
    api_key="sk-你的密钥",
    base_url="https://api.deepseek.com"
)

draft = Path("政策草案.txt").read_text(encoding="utf-8")

prompt = f"""你是一名公共政策仿真分析师。以下是某地拟出台的政策草案：
---
{draft}
---
请完成以下任务，并用 JSON 格式输出：
1) "stakeholders"：列出受影响的利益相关方（至少 5 类，如居民、基层工作人员、技术供应商等）；
2) 对每一类，给出影响方向（正面/负面/中性）和影响强度（1-5 分）；
3) "risks"：列出 3 个主要实施风险；
4) "suggestions"：给出 3 条优化建议。
"""

resp = client.chat.completions.create(
    model="deepseek-chat",
    messages=[
        {"role": "system", "content": "你是政策仿真专家，只输出合法 JSON，不要输出其他文字。"},
        {"role": "user", "content": prompt},
    ],
    temperature=0.5,
)

result = resp.choices[0].message.content
Path("仿真结果.json").write_text(result, encoding="utf-8")
print(result)
```

运行后打开 `仿真结果.json`，你会看到一份结构化的"影响矩阵"。

### 第 3 步　让 AI 把矩阵讲成人话

JSON 适合机器读，不适合人读。再问一次，让它生成"政策影响分析报告"：

```python
from openai import OpenAI
from pathlib import Path

client = OpenAI(
    api_key="sk-你的密钥",
    base_url="https://api.deepseek.com"
)

sim = Path("仿真结果.json").read_text(encoding="utf-8")

prompt = f"""请根据以下政策仿真结果，写一份《政策影响分析报告》：
一、政策概述；二、利益相关方影响分析（按影响强度排序）；三、主要风险；
四、优化建议。语言通俗，适合向非技术领导汇报。

仿真结果：
{sim}
"""

resp = client.chat.completions.create(
    model="deepseek-chat",
    messages=[{"role": "user", "content": prompt}],
)
Path("政策影响分析报告.md").write_text(resp.choices[0].message.content, encoding="utf-8")
print("已生成：政策影响分析报告.md")
```

### 第 4 步　人工修正（模拟仿真必须有的最后一步）

- AI 列的影响方和风险**可能漏掉你专业课上学的关键因素**（比如财政承受能力、数据安全合规），补充进去；
- 影响强度是 AI 的估计，不是实测数据，报告里要如实说明；
- 用你自己的专业判断定稿。

> 记住：**AI 的仿真结果 = 高质量的"头脑风暴清单"，不是"研究结论"**。真正的研究结论需要数据支撑和你的专业判断。

## 4.6 省钱省时技巧（实践后回头看）

1. **先小样测试，再全量跑**：先让脚本处理 3 条数据，确认输出满意，再放开处理全部——避免浪费钱跑出垃圾结果。
2. **控制输入长度**：长文档只喂关键段落（比如截取前 6000 字），`text[:6000]` 就是干这个的。
3. **能本地算的别用 API**：关键词统计、去重、清洗用 pandas/jieba 本地算，API 只做"理解与生成"。
4. **温度调低**：分析类任务 `temperature=0.3` 或 `0`，回答更稳定、更少胡说。
5. **保存中间结果**：每步结果都存成文件（JSON/MD），万一后面出错不用重跑前面。
6. **选择合适模型**：简单任务用便宜的对话模型；需要深度推理再考虑更强的模型（以平台文档为准）。
7. **善用 Coding Plan**：写脚本、改代码、修 bug 全部在 Cursor 里做，这部分不花 API 的钱。

# 第 5 章　层次四：AI Agent（智能体）

## 5.1 Agent 是什么

前面三层的共同点：**每一步都是你发起的**。Agent（智能体）的不同在于：**你给一个目标，它自己拆解任务、调用工具、逐步完成**。

打个比方：
- 层次一～三：你指挥 AI 干活，它干一步停一步；
- 层次四：你当"项目负责人"，Agent 当"项目经理"，你只看结果、把关质量。

## 5.2 你其实已经在用 Agent 了

Cursor 里的对话面板就是最简单的 Agent 形态：你让它"写一个脚本，读取 PDF、提取文本、保存成 txt"，它会自己写代码、创建文件、甚至运行。你给目标，它自主完成。

再比如我（Codex）就是 Agent：你提出目标，我会规划步骤、读写文件、运行命令、产出成果。

**大一阶段你不需要自己"开发"Agent**，会"使用"现成 Agent 工具就够了：

| 工具 | 适合场景 | 说明 |
|---|---|---|
| Cursor | 写代码、改代码 | 免费版够用 |
| Claude Code | 命令行里的全能 Agent | 需要订阅或 API，进阶再试 |
| Codex（现在这个） | 完成任务、产出文件 | 学会把目标描述清楚最重要 |

## 5.3 进阶示例：让 Agent 定期追踪政策动态

假设你想"每周追踪广东省数字治理相关政策动态"。思路有两种：

**方案 A（简单，推荐大一先用）**：每周手动触发一次。
1. 准备一个 `追踪政策.py`：它用 `requests` 库打开政府网站政策列表页，把标题抓下来。
2. 用 API 让 AI 筛选出与"数字治理"相关的标题并生成摘要。
3. 每周花 10 分钟运行一次，把结果整理成简报。

**方案 B（自动，大二以后再折腾）**：
1. 把脚本设置成定时运行（macOS 用"日历"或"启动台"里的自动化；Windows 用"任务计划程序"）。
2. 用 API 的"让 AI 写邮件"功能，让 AI 把简报发到你的邮箱。
3. 你需要先学"邮件发送"的 API 用法，这部分等你有基础后让 Cursor 帮你写。

> 提醒：方案 B 涉及定时任务和邮件，容易踩坑，**大一先不要追求全自动**，把"每周手动跑一次"做好就非常优秀了。

## 5.4 Agent 的边界：什么不能交给它

- **不能**：替你做涉及个人隐私、金钱、法律效力的决定；替你写作业冒充原创。
- **应该**：让它"先出方案，你审核后执行"。比如让它先列出步骤清单给你看，确认再动手。
- **原则**：**Agent 是"效率工具"，不是"甩手掌柜"**——你永远是最终责任人。

# 第 7 章　常见问题排查（FAQ）

遇到报错先别慌，大多数问题就这几种。**报错信息是最好的线索，把它复制给 Cursor，让 AI 帮你修。**

### 7.1 运行脚本报 `ModuleNotFoundError: No module named 'xxx'`

原因：库没装上（或装到了另一个 Python 环境）。
解决：运行 `pip3 install xxx`（把 xxx 换成报错里的名字），再重跑。

### 7.2 报错 `AuthenticationError` 或 `401`（认证失败）

原因：API Key 不对、过期或没粘贴对（可能多了空格）。
解决：检查 `api_key="sk-..."` 里的内容是否与平台上的完全一致；重新复制粘贴；确认没有余额（看第 7.4 条）。

### 7.3 报错 `Connection error` 或超时

原因：网络不通，或平台暂时不可用。
解决：检查网络；等几分钟重试；如果反复失败，确认接口地址 `base_url` 写的是 `https://api.deepseek.com`（不要加多余字符）。

### 7.4 报错 `Insufficient Balance`（余额不足）

解决：去平台充值页面充值（10 元够用很久）；或检查是不是有大循环不小心跑太多。

### 7.5 报错 `InvalidRequestError` 或 `400`

原因：请求内容有问题（比如文本太长超限、格式错误）。
解决：把喂给 AI 的文本截短（如 `text[:6000]`）；检查 messages 格式是否和示例一致。

### 7.6 PDF 提取出来是空的或乱码

原因：有些 PDF 是扫描件（图片），没有文字层。
解决：先确认文件是不是扫描件；扫描件需要 OCR（文字识别），可以先让 Cursor 教你用 `paddleocr` 或在线工具处理；或在政府网站找 HTML/Word 版本替代。

### 7.7 画图时中文显示成方块

原因：matplotlib 默认字体不含中文。
解决：代码开头加上第 4.3/4.4 节那两行 `plt.rcParams[...]`；如果还不行，让 Cursor 根据你的系统推荐字体。

### 7.8 脚本跑一半报错，前面的结果白跑了？

解决：把每步结果及时存文件（`json`/`csv`）；在循环里加 `try ... except` 跳过单条错误，例如：

```python
for i, text in enumerate(texts):
    try:
        resp = client.chat.completions.create(...)
        results.append(resp.choices[0].message.content)
    except Exception as e:
        print(f"第 {i} 条失败：{e}，跳过")
```

### 7.9 担心费用失控？

- 练习阶段每次跑之前，先数一下循环次数 × 文本长度，心里有数；
- 用第 4.6 节技巧控制；
- 平台后台有"用量统计"，定期看一眼；
- 实在担心，就只充 10 元——上限在那，花完就停。

# 附录 D　给 AI 助手的约定：安装/下载安全准则

> 约定人：吴宣澄　｜　生效日期：2026-08-05
> 这条准则约束的是"帮你操作电脑的 AI 助手"（比如 Codex），而不是你本人。

## 7 条必须遵守的检查

1. **来源可靠**：只从官方官网或官方应用商店下载，不用来路不明的镜像站、破解站、第三方转载。
2. **下载地址正规**：核对网址是否为官方域名，防止仿冒钓鱼。
3. **文件完整**：下载后核对官方校验值（checksum），确认文件未被篡改、未下载不完整。
4. **版本兼容**：确认软件适配本机芯片、系统版本和运行环境。
5. **安装方式规范**：优先用官方安装程序或应用商店；不使用"解包硬装"等绕过手段。
6. **装后验证**：检查签名有效、能正常启动、核心功能正常，验证通过后才交付使用。
7. **权限最小化**：只申请完成任务所需的最小权限，不附带安装捆绑软件。

## 最重要的原则

> 如果某个操作无法验证安全性、或存在风险，**先停下来告知用户**，绝不擅自继续。

## 背景

2026-08-05 安装 Cursor 时，AI 助手使用非标准解包方式破坏了应用签名，导致应用无法打开。经此教训，用户明确要求：以后安装/下载任何东西前，必须先检测安全性和稳定性。

# 附录 E　用 AI 不废武功的 5 条纪律

> 一句话：AI 是"陪练"，不是"代打"。它能替你跑，但不能替你长。

1. **先自己写，再让 AI 点评**：写作业先自己憋出第一稿（哪怕很烂），再问 AI"帮我挑毛病、给改进建议"。让 AI 当批改老师，不当代笔。
2. **结构必须你自己搭**：可以让 AI 提供材料、灵感和素材，但大纲和核心论点必须是你的。谁搭结构，谁掌握作品的灵魂。
3. **每周留一段"无 AI 时间"**：比如每周手写一篇 500 字观点短文，或默写本周学过的概念——模拟考试状态，训练徒手能力。
4. **考试前"断网复习"**：复习时不开 AI，用自己的话复述、默写。用 AI 复述知识 = 你以为会了，其实没会。
5. **定期自检**：每月问自己："如果明天 AI 突然消失，我还能独立完成核心任务吗？"答案若是否定的，说明依赖过度，该补基本功了。

> 为什么对数字公共治理专业尤其重要：未来你是评估、治理 AI 的人。一个从没自己写过分析的人，无法判断 AI 的分析好不好；一个不会自己干活的人，无法为 AI 干出来的活负责。

# 附录 F　Coding Plan 与 API 的本质区别（进阶版）

**一个项目里有两个 AI，在不同时间、干不同的活：**

| 阶段 | 谁在动脑 | 用什么 | 花谁的钱 |
|---|---|---|---|
| 写脚本、改脚本、修 bug（开发时） | Coding Plan | Cursor / Composer | Cursor 订阅 |
| 脚本运行、批量分析（运行时） | API | 脚本里的 API 调用 | 模型平台余额 |
| 读 PDF、清洗、画图（本地计算） | 无（代码） | Python 库 | 免费 |
| 核验、改报告 | 你 | —— | —— |

**三个关键认知：**

1. **上下文成本被"转移"而不是"消失"**：开发时的大量对话发生在一次性阶段，走包月订阅；运行时每次调用只带最小必要内容，没有历史堆积，所以几乎不存在上下文冗余。
2. **API 按 token 计费，不是按次**：费用 = 输入 + 输出 token，跟内容长度成正比。省钱的真正关键是"每次调用小而聚焦"（如 `text[:6000]` 截断），而不是调用次数少。
3. **上下文控制是设计原则**：一份文件一次调用、每次只带一个清晰指令。把"每次该问什么"提前设计好并固化进脚本，是工作流的核心价值。

**脚本的三个隐藏价值：**
- **可复用**：换主题只改数据源，工作流不用重写；
- **可审计**：同一脚本 + 同一输入 = 同一输出，过程可复现、可留档、可向别人解释（公共治理的立身之本）；
- **可换模型**：改一行 base_url 和 model，就能在云端 / 本地模型之间切换。

# 附录 G　为什么要自己运行脚本

> 澄清：这不需要你会编程，只需要会"点运行 + 看结果 + 填参数"。

1. **你是电脑的主人**：有些操作和文件（密码、密钥、隐私数据）AI 不该碰，必须你自己跑；
2. **工作流要"无人值守"**：周报、定期追踪等脚本要自动重复跑，不能每次靠 AI 召唤；
3. **验证与审计**：能复现、能解释、能为流程负责，是公共治理从业者的核心能力；
4. **换工具也自由**：学校机房、实习电脑、别的 AI 工具上，你依然能干活；
5. **最佳姿势**：AI 生成工作流 + 你运行 + 你核验。AI 负责快，你负责会和判断。

# 附录 H　把本地模型接进工作流（LM Studio / Hermes）

**本地模型的价值：**
- **免费**：不花 API 的钱，想跑多少次跑多少次；
- **隐私**：数据不出你的电脑，适合不想上传的作业数据、舆情评论、未公开资料；
- **无限试错**：可以大胆实验提示词，不用心疼余额。

**关键事实**：LM Studio 可以开一个"本地服务器"，地址是 `http://localhost:1234/v1`，接口格式和 DeepSeek 完全兼容（都是 OpenAI 格式）。所以**手册里所有脚本，只需要改一行 base_url**，同一个工作流就能切到本地模型跑——这就是附录 F 说的"可换模型"的实战。

**三步接进工作流：**

1. 打开 LM Studio → 左侧 Models → 下载一个中文本地模型（建议 7B～14B 的量化版，比如 Qwen 系列）；
2. 在 LM Studio 右侧打开 **Local Server（本地服务器）**，启动后地址是 `http://localhost:1234/v1`；
3. 把脚本里这两行改成：

```python
base_url="http://localhost:1234/v1"   # 指向本地模型
model="你下载的模型名"                  # 例如 qwen2.5-7b-instruct
```

**模型分工（路由原则）：**

| 任务类型 | 用谁 | 例子 |
|---|---|---|
| 简单批量 | 本地小模型 | 情感分类、关键词、短文本摘要、翻译、打标签 |
| 复杂分析 | 云端 DeepSeek | 长政策文件分析、对比推理、仿真、重要报告 |
| 隐私数据 | 一律本地 | 不想上传的评论、作业、未公开资料 |

**Hermes agent 的定位**：如果它是能自主行动的 Agent，适合做"本地小助手"——自动整理文件夹、批量给评论打标签、把网页转成摘要。但本地小模型做 Agent 能力有限，遇到复杂推理会翻车，所以"简单任务自动化"才是它的主场。

**三个提醒：**
1. 本地小模型质量明显弱于云端大模型，**重要结果必须核验**；
2. 本地服务器没启动时，脚本会连接失败；
3. 模型大小受电脑内存限制，太大了跑不动。
