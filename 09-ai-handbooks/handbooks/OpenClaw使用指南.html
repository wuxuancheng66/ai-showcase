一、OpenClaw 是什么

OpenClaw（前身 Moltbot / Clawdbot，社区昵称"龙虾 🦞"）是一个 开源、自托管的个人 AI 智能体框架，由 PSPDFKit 创始人 Peter Steinberger 发起，OpenClaw Foundation 维护，MIT 协议免费开源。它由 Peter Steinberger 发起，OpenClaw Foundation 维护，MIT 协议免费开源（GitHub 已超过 6.8 万 star，是最快爆火的开源 AI 项目之一）。

它的定位可以一句话概括：给大模型装上"双手"的执行引擎 + 24 小时待命的本地管家。传统 ChatGPT 只能"说"，OpenClaw 能"做"——读写文件、跑命令、控制浏览器、定时执行任务，并通过你已经在用的聊天软件与你对话。

二、核心功能

🧠

本地网关 Gateway

统一控制中枢：管理会话、工具、事件和渠道连接。一个网关同时服务个人和团队，模型、工具、权限都在这里集中调度。

🖥️

Control UI 控制面板

浏览器里的可视化界面（就是你现在打开的 127.0.0.1:18789）：聊天对话、实时观看智能体干活、搜索历史会话、管理配置与工具。

💬

多渠道接入

把助手接进你已有的聊天软件：Raft、WhatsApp、Telegram、Discord、Slack、Signal、iMessage、Google Chat、Microsoft Teams、Matrix、Zalo 等。手机也能随时指挥。

🛠️

工具系统（真能动手）

读写本地文件、执行 Shell 命令、运行脚本、控制浏览器（填表单、抓网页数据）、连接 MCP 服务器扩展能力。

📚

Skills 技能库

100+ 现成技能可直接安装；还能用 /learn 让它根据你的对话自动起草新技能，实现"自我进化"。

🧩

插件生态 ClawHub

插件 SDK + 官方插件市场，支持从 ClawHub / npm / git 安装插件，持续扩展新能力。

🧠

持久记忆

记忆以本地 Markdown 文件存储（身份、用户偏好、长期记忆），透明可读、可手动编辑，跨会话个性化。

⏰

自动化与定时任务

内置 cron 定时任务、Webhook 触发、事件驱动 hooks——你睡觉时它也能替你干活。

🔌

模型中立 BYOK

不绑定任何一家：可用 OpenAI、Claude、Gemini、智谱等云端模型，也可接 Ollama 本地模型，自己带 Key、自己选性价比。

👥

子智能体与团队协作

支持 subagents 子任务路由、隔离工作区；2.0 起支持共享会话，团队成员可加入同一会话接力干活。

🗣️

语音与多模态

TTS 语音回复、Talk 模式、手机节点调用摄像头/屏幕/定位等设备能力。

🔐

安全与审批

陌生私信默认需配对审批、高危操作需 Exec 审批、可配置沙箱隔离、按角色最小权限授权。

2.0 版本新增亮点（2026.8.1）

  • 全新控制面板：聊天置顶、可观看智能体实时干活，界面更像主流 AI 产品。
  • 小组件与事件看板：widgets 可钉到仪表盘、绑定事件触发动作。
  • 共享会话（多人协作）：团队可加入同一会话继续未完成的工作、带上下文交接任务。
  • 历史会话搜索：按精确文本/关键词检索过往对话，一键回到上下文。
  • 安装更省心：自动探测已有模型订阅、API Key 与本地模型，默认配置即可开聊。
  • 安全强化：明确信任边界、最小权限、更强的提示词滥用防护。

三、如何使用它

3.1 用控制面板聊天（你现在的位置）

  • 打开 http://127.0.0.1:18789/，进入 /chat/main 即可直接对话。
  • 像用 ChatGPT 一样发消息；它会自动调用工具执行任务，并在界面上显示运行过程。
  • 输入 / 可看到全部斜杠命令；/new 新建会话、/model 切换模型、/help 查看帮助、/tools 查看当前可用工具、/skill 运行技能。

3.2 在聊天软件里指挥它（渠道）

  • 你的实例已接入 Raft 团队聊天：在 Raft 里直接给它发消息即可，手机上也能用。
  • 想加更多渠道（Telegram/WhatsApp/Discord 等）：终端运行 openclaw channels add 按向导添加。
  • 陌生人私信默认需配对：openclaw pairing approve <渠道> <码> 审批后才可对话。

3.3 常用 CLI 命令

openclaw status              # 查看网关/渠道/模型健康状况
openclaw dashboard           # 打开控制面板
openclaw doctor --fix        # 一键诊断并修复常见问题
openclaw configure           # 交互式修改模型/渠道/插件配置
openclaw channels status     # 查看已连接的聊天账号
openclaw models status       # 查看模型供应商鉴权状态
openclaw gateway status      # 查看网关运行详情
openclaw sessions list       # 查看历史会话
openclaw memory search <词>  # 搜索长期记忆
openclaw update              # 更新到最新版

3.4 配置与数据

  • 主配置在 ~/.openclaw/openclaw.json；工作区（记忆/技能/文件）在 ~/.openclaw/workspace。
  • 修改配置建议用 openclaw configure 或 openclaw config set ...，自动校验，避免手改出错。

3.5 让它干活（几个示范）

  • "帮我把这份 PDF 的重点整理成一份周报" —— 文件读写 + 生成文档
  • "每天早上 8 点把最新 AI 资讯摘要发到 Raft" —— 定时任务 + 渠道
  • "登录这个网站，把表单填好提交" —— 浏览器自动化
  • "把刚才这个工作流保存成一个技能" —— /learn 自我进化

五、安全注意事项

高危：OpenClaw 有执行 Shell、读写文件、控制浏览器的能力，等于"能动手的钥匙"。请遵守以下安全底线：
  • 保持仅本机监听：你当前是 loopback（127.0.0.1）模式，很安全。不要随意把网关暴露到公网；确需远程访问优先用 Tailscale 等内网方案。
  • 陌生人私信先配对：默认 DM 渠道陌生人不配对不可对话，收到配对请求用 openclaw pairing approve 审批。
  • 高危操作审批：Shell 等敏感工具建议走 exec 审批，需要时再批准，不要长期放开。
  • 插件来源谨慎：优先用 ClawHub 官方目录和受信插件；第三方插件安装前先看来源。
  • 定期体检：跑 openclaw doctor 和 openclaw security 检查常见安全配置隐患。

七、TTS 语音回复（你的机器尚未配置）

当前状态：你的 OpenClaw 还没有配置 TTS（配置里无 tts 块，也没有本地偏好文件），需要先启用才能用。好消息是：有免费方案，不需要任何 API Key。

它能做什么

  • 把助手的回复转成语音：在 Telegram / WhatsApp / 飞书 / Matrix 上是原生"语音留言"，其他渠道（包括 Raft）以 音频附件（MP3） 形式发送。
  • 支持 14 个语音提供商：OpenAI、ElevenLabs、Google Gemini、Azure、MiniMax、火山引擎、小米 MiMo 等；Microsoft 和"本地 CLI"两种无需 API Key。
  • 可固定"人设声音"（persona）、中文自动切换（Microsoft 对中文回复自动用 zh-CN-XiaoxiaoNeural）、长回复自动摘要后再朗读、模型可在回复里内联 [[tts:...]] 指令自己控制语气。

三种开启方式（按推荐排序）

  1. 免费立刻体验（Microsoft）：无需任何 Key。编辑 ~/.openclaw/openclaw.json 加 tts: { auto: "always", provider: "microsoft" }，或先跑 openclaw doctor --fix 后直接在聊天里 /tts on 试。
  2. 复用你已有的模型 Key（OpenAI）：若模型用的是 OpenAI，配置 tts: { provider: "openai" }，即可用 gpt-4o-mini-tts，声音可选 alloy / cedar / coral 等。
  3. 进阶（ElevenLabs）：声音最自然、支持克隆声音、多语言，需要 ELEVENLABS_API_KEY。

八、合盖休眠后 OpenClaw 还能常驻工作吗？

直接结论

  • 合盖进入睡眠后，OpenClaw 会暂停：不回复消息、不执行定时任务、浏览器/文件等工具全部不可用（整个系统都睡了）。
  • 唤醒后自动恢复：你的网关是 LaunchAgent（KeepAlive=true、登录自启），系统一醒它就接着工作；只是睡眠期间错过的 cron 任务不会补跑（社区已知限制）。
  • 所以想让它 24/7 真正常驻，核心是"让电脑不睡"。

你机器目前的实际情况（已检测）

项目状态含义
防睡眠服务✅ 有 com.user.openclaw-keepawake（caffeinate -s，已运行 3 天+）插电时能阻止"空闲睡眠"，放着不动不会睡
外接显示器❌ 当前无（仅内置屏）没有外接屏时，MacBook 合盖仍会强制睡眠
网关服务✅ LaunchAgent 常驻 + KeepAlive进程崩溃自动重启、登录自启
系统睡眠定时sleep=1（已被 caffeinate 按住）空闲 1 分钟即睡，但当前被防睡眠断言阻止

想要"合盖常驻"，三种可行方案

  1. 合盖模式（Clamshell）— 最接近你想要的：给 MacBook 接上电源 + 外接显示器（+ 外接键鼠），合盖后系统会继续运行，OpenClaw 照常工作。缺点：必须有外接屏，且建议插电。
  2. 换/加一台常开设备 — 社区主流做法：Mac mini、旧笔记本（开盖插电 + 系统设置永不睡眠）、云服务器、NAS 跑网关。一劳永逸，还不用每天背着"笔记本当服务器"。
  3. 保持开盖使用：外接键鼠 + 显示器，把系统"锁定屏幕/电池"的睡眠都设为"永不"（仅插电时），配合你现有的 caffeinate 即可 24/7 运行。
别指望纯软件：MacBook 合盖睡眠优先级高于任何软件（caffeinate、Amphetamine 都挡不住），没有外接显示器时合盖必睡。OpenClaw 官方目前也没有内置防睡眠功能（社区已提 feature 请求 #15444）。
顺带提醒：如果你主要依赖定时任务（日报、自动归档），请务必让网关所在设备保持不睡；否则睡眠期间的定时任务会错过，醒来也不会补跑。

这个 keep-awake 服务耗电吗？（已实测评估）

  • 进程本身可忽略：caffeinate -s 只占 32KB 内存、0.0% CPU（实测已连跑 3 天+），成本趋近于零。
  • 真正的"耗电"是让电脑保持不睡：插电时黑屏待机约 5–15W，一天约 0.1–0.3 度电，按居民电价折合约 0.1–0.2 元/天，可忽略。
  • 电池模式下它完全不生效：-s 仅在插电（AC）时有效，所以拔电用笔记本时续航不受影响，系统照样空闲 1 分钟后休眠——代价是电池模式下 OpenClaw 不会常驻。
